# 031-F Agent harness engram-aware workflow hardening

<!-- SECTION:DESCRIPTION:BEGIN -->
## Description

Tighten the agent harness so subagent workflows leverage engram and file-based persistence consistently. Four cross-cutting concerns:

1. **File-loaded verification** — agents should be able to confirm a file is indexed in engram before they reference it as authoritative context (sources/files often referenced before file-watcher catches up).
2. **Bug logging into the harness** — current bug discoveries are scattered across memory files and PR comments. Need a structured `bugs/` capture surface that feeds CE learning loop.
3. **File-first content production** — research, bug analysis, and large-output decisions should write to file first, then be consumed via engram graph/vector/document store, especially in cheaper subagent calls. Reduces context burn.
4. **Workflow policy clarification** — formalize whether decomposition (research → plan → features → tasks) is universal, and whether one-feature-per-branch-through-PR is policy.

This is high blast radius — touches instruction files, agent definitions, and skill protocols across the harness. Plan hardening required.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

<!-- AC:BEGIN -->
- [ ] Agents have a documented protocol (in agent-engram.instructions.md or a skill) for verifying engram has indexed a file before treating it as authoritative.
- [ ] A `bugs/` capture mechanism exists with documented format and ingestion path into compound learning.
- [ ] At least one cheap-subagent skill demonstrates file-first content production with engram-mediated retrieval.
- [ ] A workflow-policy document or instructions update states the decomposition policy and branch-per-feature policy explicitly (or explicitly rejects them with rationale).
<!-- AC:END -->
