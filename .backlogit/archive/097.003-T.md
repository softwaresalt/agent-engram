W2 — validate multipart-identifier components against the unquoted Spark identifier grammar; reject malformed component tokens. Domain: lineage-model (single file, distinct function from V5). Plan Unit W2.

PROBLEM. `LineageAuthorityContext::resolve_table` (src/models/lineage.rs L167; part split at L177) validates only `parts.len() == 3`, non-empty parts, and the existing `::`/`:` delimiter-collision guard. It does NOT validate each of the three `catalog.schema.table` components against the unquoted Spark identifier grammar. A malformed component token — embedded whitespace, quote, hyphen, leading digit, or other punctuation — survives and binds a false `table::{authority}::{name}` endpoint.

CHANGE. Add `fn is_spark_unquoted_identifier(component: &str) -> bool` in src/models/lineage.rs matching the unquoted Spark identifier grammar `^[A-Za-z_][A-Za-z0-9_]*$` (non-empty; first char letter or underscore; remaining chars letter/digit/underscore). In `resolve_table`, after the 3-part / non-empty check and BEFORE the existing `::`/`:` collision guard, reject (return `None`) any literal where any component fails `is_spark_unquoted_identifier`.

FILE TARGETS. src/models/lineage.rs only (new predicate + `resolve_table` call-site + tests in the existing `tests` module).

ACCEPTANCE CRITERIA (test-first):
- AC1 (malformed rejected): 3-part literals with a component containing whitespace, `"`/`` ` ``, a hyphen, a leading digit, or other punctuation resolve to `None` (no `table::` endpoint bound).
- AC2 (clean preserved): a well-formed `cat.schema.table` with all components matching the grammar still resolves to its authority-embedded endpoint (no recall regression).
- AC3 (invariant intact): the existing `::`/`:` injectivity collision guard still returns `None` on its cases (no regression of the canonical-id guard).

FAIL-CLOSED INVARIANT. Only DROPS malformed identifiers (013-D precision floor: 0 false edges). Quoted identifiers remain out of v1 (already dropped) — W2 validates the UNQUOTED grammar only. SAME-FILE NOTE (build sequencing, NOT a logical dependency): shares src/models/lineage.rs with V5 (097.002-T) and X1 (097.006-T); serialized by the single-branch build model, so no `blocks` edge between V5 and W2.

Harness-ready: RED negative/positive unit tests then GREEN via the predicate. No schema/API change. Parallel with V2/V5/W1/V4; feeds X1 version bump.
