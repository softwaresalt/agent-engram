## Return Fast IndexInProgress from sync_workspace

## Problem

`sync_workspace` (in `src/tools/write.rs`, line ~187) does not check `is_indexing()` before proceeding. When the daemon is actively indexing (holding the CozoDB write lock), the sync handler blocks waiting for the lock. The IPC transport times out after 30s, returning a cryptic error:

```
IPC failure: IPC request timed out after 30000ms
```

No indication is given that indexing is in progress and sync should be retried later.

**Root cause**: `sync_workspace` calls `code_graph::sync_workspace()` which internally acquires the DB connection and blocks on the write lock.

## Fix

Add an `is_indexing()` guard at the top of `sync_workspace`, returning `CodeGraphError::IndexInProgress` immediately. This matches the pattern already used by `index_workspace` (which uses `try_start_indexing()` + rejects with `IndexInProgress`).

Additionally, update the CLI `sync` subcommand in `src/cli/runner.rs` to detect the `IndexInProgress` error code and print a user-friendly message:

```
Indexing is in progress. Sync will be available after indexing completes. Try again shortly.
```

## Acceptance Criteria

- `sync_workspace` returns `IndexInProgress` within <100ms when indexing is active (no 30s timeout)
- CLI `engram sync` prints a human-readable message when `IndexInProgress` is returned
- Contract test verifies `sync_workspace` returns correct error code during indexing
- `cargo test` passes
- `cargo clippy -- -D warnings -D clippy::pedantic` clean

## Scope

- `src/tools/write.rs` — add `is_indexing()` guard to `sync_workspace`
- `src/cli/runner.rs` — detect and format `IndexInProgress` error in sync response
- `tests/contract/` — contract test for sync during indexing
