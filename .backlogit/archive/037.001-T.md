title: Move run_schema_bootstrap inside spawn_blocking closure in connect_db
updated_at: 2026-05-02T00:00:00Z
---

Move `schema::run_schema_bootstrap(&cozo_db)` inside the `spawn_blocking` closure in `connect_db` (`src/db/cozo_backend/mod.rs`) so the advisory fd-lock is held for both `DbInstance::new` and schema bootstrap. Construct `CozoDb { inner: Arc::new(db) }` inside the closure, call `run_schema_bootstrap`, then return the `CozoDb`. This eliminates the intra-process SQLITE_BUSY race where parallel callers could both reach schema bootstrap concurrently.

## Acceptance Criteria

- `run_schema_bootstrap` runs inside the `spawn_blocking` closure, before `_guard` drops
- `CozoDb` is constructed inside the closure
- `connect_db` returns the fully-bootstrapped `CozoDb`
- Existing tests pass: `cargo test --features cozo-backend`
- Doc comments on `connect_db` updated to reflect expanded lock scope
