NEW (Amendment 1, 2026-07-03). OVERTURNS decision-017 D9/A2: the CLI-direct (daemonless) path must ALSO emit usage telemetry, because the operator MCP-fallback scenario is "daemon unavailable -> use the CLI (--direct)". Width: cli/direct.

Grounding: run_direct_sync BYPASSES tools::dispatch (it calls services::code_graph::{index,sync}_workspace_with_progress directly) and emits nothing today. There is NO shared choke point with the daemon, so this is a minimal DEDICATED hook, not a dispatch extension.

Scope:
- src/cli/direct.rs (run_direct_sync): accept `correlation_id: Option<String>`; after the code_graph call, build a UsageEvent (tool_name=sync_workspace|index_workspace, pinned ISO-8601-UTC timestamp, latency_ms from started_at.elapsed(), workspace, branch, outcome, correlation_id, schema_version=2) and emit via metrics::initialize -> metrics::record -> metrics::shutdown().await (shutdown DRAINS the mpsc before the short-lived process exits so the record is not lost). Reuses the SAME append/rotation path as the daemon (067.003-T) -> byte-compatible output.
- src/cli/commands/indexing.rs (run_sync, run_index): thread flags.correlation_id into run_direct_sync.

Concurrency: direct mode holds DaemonLock for the whole run -> daemon and direct never write the same usage.jsonl concurrently (mutual exclusion). Honor MetricsConfig.enabled (opt-out) — skip cleanly when disabled.

Tests (integration, ≤4): (1) `engram sync --direct --correlation-id X` appends a record with correlation_id=X + ISO-8601-UTC timestamp + matching tool_name; (2) --direct without the arg omits correlation_id; (3) ENGRAM_CORRELATION_ID env path populates the record; (4) metrics disabled -> no record.

Depends on 067.003-T (emitter/rotation path) and 067.005-T (flags.correlation_id field).
