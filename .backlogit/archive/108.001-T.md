Source stash 75DAF33D (medium bug, PR #301 follow-up). A non-forced ordinary index that authoritatively reads an indexed file as zero bytes can retain stale raw call rows when another file hash-skips. Add sync-parity empty-read eviction: immediately after successful content read and before hash/parse, use existing handle_deleted_file for an indexed zero-byte path; never act on metadata or read failure. Preserve files_reconciled meaning, count the path as skipped, and add no response fields.

<!-- BEGIN:acceptance-criteria -->
- RED first in a disposable workspace: ordinary-index an edge-bearing file plus unchanged control, then rewrite only the edge-bearing file to zero bytes.
- The next non-forced index hash-skips the control yet removes the empty path's code-file record, symbols, staged calls, and all direct/resolved/raw dangling rows.
- The unchanged control and live edges remain; marker does not advance on the hash-skipped run.
- A never-indexed empty file is no-op. Metadata zero, read failure, parse failure, and non-empty files are not deletion authority.
- files_reconciled and all public/CLI/MCP/schema contracts remain unchanged; no new deletion primitive.
- Ship never reads for repair, reindexes, repairs, or mutates an operator workspace; approval does not widen that boundary.
<!-- END:acceptance-criteria -->

Stop for non-empty/read-failed cleanup, lost control, generalized teardown, >declared scenarios/files, or any non-disposable workspace action.
