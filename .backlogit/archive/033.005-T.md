## Description

Enable `CREATE PROCEDURE` symbol extraction once a published `tree-sitter-sequel`
release includes upstream PR #355. The parser already has a forward-compat
match arm for `create_procedure`; the remaining work is to adopt the released
grammar, flip the current graceful-degradation test into a positive assertion,
and remove the stale caveat in the SQL parser documentation.

Source: stash `19D78639` - "SQL parser: CREATE PROCEDURE, FUNCTION DDL support"

## Scope

- `Cargo.lock` via `cargo update -p tree-sitter-sequel` once a qualifying
  release is published
- `tests/unit/parsing_test.rs` to turn `test_sql_create_procedure` into a
  positive assertion and keep `CREATE FUNCTION` coverage green
- `src/services/parsing/sql.rs` module docs to remove the stale ERROR-node
  caveat after the upgrade

## Blocker

Upstream grammar support is already merged in `derekstride/tree-sitter-sql`
PR #355, but crates.io has not published a `tree-sitter-sequel` release newer
than `0.3.11`. This task stays blocked until a published release contains
PR #355 and can be pulled with `cargo update -p tree-sitter-sequel`.

Track:
- https://github.com/derekstride/tree-sitter-sql/releases
- https://github.com/derekstride/tree-sitter-sql/pull/355

## Acceptance Criteria

- `cargo update -p tree-sitter-sequel` pulls a release that includes PR #355
- `test_sql_create_procedure` extracts one `ExtractedSymbol::Function` named
  `archive_old_orders`
- existing `CREATE FUNCTION` coverage stays green
- `src/services/parsing/sql.rs` no longer documents `CREATE PROCEDURE` as an
  ERROR-node limitation
- `cargo test` passes

## Notes

Current parser logic already matches `create_procedure` in
`src/services/parsing/sql.rs`; no new production extraction arm should be
needed when the release lands. The old blocker text was stale: the missing
piece is now the crates.io release, not the upstream grammar implementation.
