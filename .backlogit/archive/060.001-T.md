## Audit `sync_workspace` Deletion Handling for Branch-DB Seeding

## Description

Read the `sync_workspace` implementation in `src/services/code_graph.rs` and
determine whether CozoDB symbol and edge records are removed when a tracked
file is deleted from the workspace. This is the Option C prerequisite from
deliberation `008-D` before any branch-DB seeding work can proceed.

Source: deliberation `008-D`, open question 1.

## Scope

- `src/services/code_graph.rs` — `sync_workspace` (line 627) and its
  deletion-handling branches
- `src/services/file_tracker.rs` — how removed files are detected and
  reported to the sync loop
- `tests/integration/` or `tests/unit/` — new test for the delete-and-resync
  scenario

## Implementation

1. Read `sync_workspace` and identify how it detects file deletions (compare
   tracked file list vs. workspace scan output).
2. Confirm whether a "file removed" branch calls the appropriate CozoDB
   relation-deletion query.
3. Write a failing test first (TDD red phase):
   - Create a temp workspace with one source file containing at least one
     function definition.
   - Run `sync_workspace` and assert the symbol exists in CozoDB.
   - Delete the file from the temp workspace.
   - Run `sync_workspace` again.
   - Assert the symbol and all edges for that file are absent from CozoDB.
4. If the test passes (deletion is correct): document the finding, mark this
   task done, and update `008-D` `## Chosen Direction` with the result.
5. If the test fails (deletion is broken): document the failure path, mark
   this task `blocked`, and create a follow-up fix task before proceeding
   with seeding.

## Acceptance Criteria

- A new integration or unit test covering the delete-and-resync scenario exists
- `cargo dev-test` passes (if deletion is correct), or a clear blocker note
  and follow-up task exist (if broken)
- The deletion-correctness finding is recorded in `008-D` `## Chosen Direction`
