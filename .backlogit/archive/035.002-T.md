## Batch-UPDATE optimization for reresolve_references_edges

## Description

Replace the N+1 round-trip pattern in `reresolve_references_edges`
(`src/db/queries.rs`) with a batch class-lookup approach. Currently the method
issues one `get_class_by_name` query per unresolved edge; batch the lookup by
collecting all unique `qualified_name` values and querying class names in a
single `SELECT name, id FROM class WHERE name IN $names`.

## Scope

- `src/db/queries.rs` — refactor `reresolve_references_edges` internals
- Return type change: `ReresolveResult { resolved: usize, lookups: usize }`
  to enable testability of batch behavior
- `tests/contract/references_edge_test.rs` — new test asserting batch behavior
  (lookups ≤ unique_names, not per-edge)

## Acceptance Criteria

- Batch class lookup reduces DB round-trips from 2N to N+1 for N unresolved edges
- Return struct includes `lookups` count for testability
- Contract test with 3+ self-loop edges asserts `lookups <= unique_names`
- All existing tests pass (behavior-preserving refactor)
- `cargo test` and `cargo clippy` pass

## Execution Posture

Test-first: write contract test with batch assertion (red on current N+1 impl),
refactor to batch lookup (green).
