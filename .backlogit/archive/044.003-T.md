## Integration Test for Tool Responses During Active Indexing

## Problem

No integration test currently validates that tools return `IndexInProgress` rather than timing out, panicking, or returning silent zeros when indexing is active. The bug was discovered only through manual CLI testing (028-S).

## Fix

Add an integration test that:

1. Spawns a daemon via `DaemonHarness`
2. Binds a workspace (triggers auto-indexing via `background_db_hydration`)
3. Immediately calls several read/write tools that should return `IndexInProgress`
4. Asserts each response contains the `IndexInProgress` error code (7xxx series)
5. Waits for indexing to complete (health → ready)
6. Re-calls the same tools and asserts they succeed

**Tools to exercise**:
- `stats` (get_workspace_statistics)
- `query_memory`
- `unified_search`
- `sync_workspace`

## Acceptance Criteria

- Integration test covers at least 4 tools responding correctly during indexing
- Test runs in the standard `cargo test` suite
- Test uses `DaemonHarness` with proper `ENGRAM_DATA_DIR` isolation (per 028-S compound learning)
- `cargo test` passes

## Scope

- `tests/integration/` — new test file `indexing_resilience_test.rs`
- `tests/helpers/mod.rs` — any shared harness utilities needed

## Dependencies

Depends on 044.001-T (read tool guards) and 044.002-T (sync guard) being complete first
