## Make CLI IPC Timeout Configurable for Long-Running Operations

## Problem

All CLI subcommands use a hard-coded 30s IPC timeout (`CLI_IPC_TIMEOUT` in `src/cli/runner.rs`, line 18):

```rust
const CLI_IPC_TIMEOUT: Duration = Duration::from_secs(30);
```

This is insufficient for:
- `engram index` (full re-index) — can take minutes on large workspaces
- `engram sync --full` — same as index
- `engram sync` — if queued-sync (044.004-T) is not yet implemented, incremental sync on a large delta can exceed 30s

The `start.ps1` / `start.sh` preloading scenario is especially affected: the script calls `engram sync` to pre-populate the code graph before launching Copilot, but the operation times out on any non-trivial workspace.

## Fix

1. Add a `--timeout` flag to `GlobalFlags` (`src/cli/flags.rs`) with a sensible default (30s for most commands)
2. In `run_tool()` (`src/cli/runner.rs`), use the flag value instead of the constant
3. For indexing-specific commands (`index`, `sync --full`), use a longer default timeout (e.g., 300s / 5 minutes) unless overridden by `--timeout`
4. Support `ENGRAM_CLI_TIMEOUT` env var as a fallback for scripted usage (start.ps1 doesn't need to pass flags)

## Acceptance Criteria

- `engram sync --timeout 120` uses 120s timeout
- `engram index` defaults to 300s timeout (not 30s)
- `engram sync` (incremental) defaults to 30s timeout
- `ENGRAM_CLI_TIMEOUT=120` env var overrides the default for all commands
- Explicit `--timeout` flag takes precedence over env var
- `cargo test` passes
- `cargo clippy -- -D warnings -D clippy::pedantic` clean

## Scope

- `src/cli/flags.rs` — add `--timeout` to `GlobalFlags`
- `src/cli/runner.rs` — use configurable timeout instead of `CLI_IPC_TIMEOUT` constant
- `src/cli/commands/indexing.rs` — pass longer default for index/sync-full
- `src/bin/engram.rs` — no changes expected (flags flow through GlobalFlags)

## Notes

This is independent of the queued-sync work (044.004-T). Even with queued-sync, `engram index` still needs a long timeout because it's a synchronous full re-index that the caller expects to complete before proceeding.
