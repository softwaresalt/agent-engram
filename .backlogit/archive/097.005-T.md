V4 [P1] — add an ingestion integration test that sets RegistryConfig.lineage, runs ingest_all_sources, and asserts an authority-bound lineage edge is produced end to end. Domain: tests/integration (single new test file, TEST-ONLY). Plan Unit V4.

PROBLEM. Lineage edge production is covered only at the unit / write-path tier (tests/integration/lineage_precision_recall_test.rs, notebook_lineage_writepath_test.rs). No test drives the FULL `RegistryConfig.lineage -> ingest_all_sources -> persisted authority-bound edge` path, so a regression in the ingestion wiring (config -> authority context -> extraction -> write) would not be caught end to end.

CHANGE. Add a new integration test file (e.g. tests/integration/lineage_ingestion_e2e_test.rs) that:
1. Builds a `RegistryConfig` whose `lineage` field (`LineageConfig`, src/models/config.rs L331; `to_authority_context` L373) is populated — a `metastore_authority_id` + a `catalog_authorities` entry (table path) and/or a `storage_authorities` entry (path path).
2. Points a source at a fixture notebook containing a resolvable authority-bound read->write (a `%%sql` CTAS/INSERT with a 3-part `cat.schema.table`, or a PySpark read->write under a trusted storage authority).
3. Runs `ingest_all_sources` (src/services/ingestion.rs L60) against a real CozoDB-backed `CodeGraphQueries`.
4. Asserts a persisted `lineage_derives_from` edge exists via `CodeGraphQueries::select_lineage_edges` (src/db/cozo_queries.rs L6088), with the expected authority-embedded endpoint ids.

FILE TARGETS. tests/integration/<new>_test.rs (+ a small fixture notebook under the test's fixtures dir). NO production-code change (width isolation — this is why V4 is not merged with V5/W2).

ACCEPTANCE CRITERIA (characterization/coverage-first):
- AC1: with `lineage` configured, `ingest_all_sources` produces exactly the expected authority-bound `lineage_derives_from` edge(s) end to end.
- AC2 (fail-closed control): with an EMPTY `lineage` config, the same fixture produces NO lineage edge (empty-context fail-closed, 013-D).

POSTURE. The write path shipped in 095-F, so this is expected to go GREEN once written. If it reveals an e2e gap (edge NOT produced despite a valid config), FILE a follow-up rather than fixing shared ingestion infra inline (freeze-scope — docs/compound/feature-test-flake-fix-in-scope-not-shared-infra-2026-07-11.md).

Harness-ready: RED harness then GREEN via existing write path. Parallel with V2/V5/W2/W1; independent of X1 (test does not change extractor output).
