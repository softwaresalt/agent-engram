The canonical-directory dedup in collect_files_in_workspace (src/services/source_traversal.rs:63-64) emits only one path per real directory when a directory symlink aliases an already-visited canonical dir. If a file was indexed under path A (e.g. z/shared.ipynb) and an earlier-sorting alias B (a/shared.ipynb) is later added, traversal emits only B, but the notebook and non-TMDL PowerBI deletion sweeps still consider A live (physical file in-bounds via is_regular_file_in_workspace). The stale A record is never removed. Fix: reconcile stored paths against the set actually collected this pass (delete records whose path was not collected), or give traversal a stable canonical identity.
