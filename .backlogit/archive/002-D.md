## Problem Frame

<!-- BEGIN:problem-frame -->
Shipment 018-S introduced an advisory fd-lock around DbInstance::new in connect_db but the lock is released before schema bootstrap runs. Parallel tests/daemons calling connect_db on the same DB path can hit the intra-process SQLITE_BUSY panic variant. CI retains continue-on-error: true until this is resolved.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A: Extend fd-lock scope to cover schema bootstrap (actionable now, low effort). Option B: Upgrade cozo to 0.8+ (blocked — 0.8 does not exist on crates.io). Option C: Both — extend lock now, track upgrade as deferred follow-up.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Option C — Extend fd-lock scope now (move run_schema_bootstrap inside spawn_blocking closure), track cozo 0.8+ upgrade as deferred backlog item. This is the only actionable path since cozo 0.8 does not exist.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
When will cozo 0.8 ship? Will it have breaking API changes? Monitor crates.io and upstream repo.
