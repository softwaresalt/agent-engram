Handle DAX '--' single-line comments consistently in every comment-aware pass. VERIFIED 2026-07-14: the DAX lexer (crates/powerbi-tmdl-parser/src/dax.rs, module doc L12-13) skips only '//' and '/* */' comments — not DAX '--' single-line comments; the Tier-1 emptiness + division scanners in src/services/dax_lint.rs (contains_bare_division) likewise ignore '--'. As a result, column/measure references and function calls appearing inside a '--' comment are emitted as real dependencies and can produce false Tier-2 broken-ref findings (and skew Tier-1 division/emptiness scans). FIX: treat '--' as a line comment (to end-of-line) everywhere '//' is handled — the lexer tokenizer and the Tier-1 scanners — being careful NOT to treat '--' inside string literals or bracketed identifiers as a comment. TEST-FIRST ACCEPTANCE: (1) failing regression fixture: a DAX expression with a '--' comment containing a fake [Column]/Table reference and a division emits NO dependency/broken-ref/division finding for the commented content; (2) '--' inside a string literal ("a--b") or identifier is NOT treated as a comment; (3) existing '//' and '/* */' handling unchanged. IMPL NOTES: extend the comment-skip states in dax.rs lexer and mirror in contains_bare_division (dax_lint.rs). Single-width: DAX lexer + Tier-1 scanner (parser crate + dax_lint). BLAST RADIUS: DAX lint correctness only (no runtime/index migration). Deferred from 080-S / PR#246 finding C4-1. Source stash 0C98C5F1.
