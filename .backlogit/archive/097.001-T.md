V2 [P1] — make the Spark-SQL INSERT-target normalizer quote-aware AND comment-aware. Domain: sql-parser (single file). Plan Unit V2.

PROBLEM. `normalize_spark_insert` (src/services/parsing/sql.rs L425) byte-scans the RAW source for the `INSERT … OVERWRITE/INTO TABLE` keyword run and rewrites it to `INSERT INTO` BEFORE tree-sitter parses (the tree-sitter-sequel 0.3 Spark-`TABLE`-keyword shim). The scan (and its helper `insert_table_prefix_end` L448 / `match_ci_word`) is neither quote-aware nor comment-aware: an `INSERT OVERWRITE TABLE` token sequence inside a line comment (`-- …`), a block comment (`/* … */`), a single-quoted string literal (`'…'`), a double-quoted identifier (`"…"`), or a backtick identifier (`` `…` ``) is wrongly rewritten, corrupting the SQL and/or minting a spurious normalization.

CHANGE. Replace the naive outer scan loop in `normalize_spark_insert` with a region-aware scan that tracks a small lexer state (normal / in-line-comment / in-block-comment / in-single-quote / in-double-quote-identifier / in-backtick-identifier) and only attempts the `INSERT … TABLE` rewrite when in the NORMAL state. Handle Spark escape conventions: doubled single-quote (`''`) inside a string literal and doubled quote/backtick inside quoted identifiers do NOT close the region. Keep `insert_table_prefix_end`, `matched_word_end`, `match_ci_word`, `skip_ws` unchanged — the fix is confined to the outer scan plus one small state helper.

FILE TARGETS. src/services/parsing/sql.rs only (`normalize_spark_insert` + a new `fn` for lexer-state advance + tests in the existing `sql_lineage::tests`).

ACCEPTANCE CRITERIA (test-first; <4 core scenarios):
- AC1 (comment): `INSERT OVERWRITE TABLE x` appearing inside a `--` line comment or `/* */` block comment is NOT rewritten and produces NO lineage edge.
- AC2 (string/identifier): the same token run inside a `'…'` string literal and inside a `"…"` / `` `…` `` quoted identifier is NOT rewritten; include an escaped-quote (`''`) fixture (P2 review finding) so early region-exit is guarded.
- AC3 (recall preserved): a GENUINE `INSERT OVERWRITE TABLE cat.schema.tbl SELECT … FROM cat.schema.src` outside any quoted/comment region still normalizes to `INSERT INTO` and emits its authority-bound `derives_from` edge (no recall regression).

FAIL-CLOSED INVARIANT. Change only removes spurious rewrites; genuine INSERT normalization is preserved (013-D precision floor: 0 false edges). Learning applied: docs/compound/best-practices/sql-quoted-identifier-resolution-candidates-list-2026-04-29.md (quote-form awareness — do NOT import the candidates-list resolution pattern; scope is the normalizer only).

Harness-ready: land a RED unit-test harness (AC1–AC3) then GREEN via the region-aware scan. No schema/API change. Parallel with V5/W2/W1/V4; feeds X1 (097.006-T) version bump.
