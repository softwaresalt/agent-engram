Source: authoritative high-priority bug stash B30EA752. Prevent GitHub Copilot CLI from appearing hung while Engram MCP starts in a native Git worktree, and close the Ship integration gap without making Ship own daemon startup or cleanup.

Grounded cause: `src/db/workspace.rs::canonicalize_workspace` accepts only a `.git` directory and `resolve_git_branch` hardcodes `.git/HEAD`; a native `git worktree` exposes a `.git` gitfile. The Stage worktree probe failed as `not a Git repository root`. `src/daemon/ipc_server.rs` binds IPC before hydration, hydration then rejects the worktree and shuts down, while `src/shim/lifecycle.rs::poll_until_ready` can consume the 30-second readiness budget. `start.ps1` can add synchronous direct/fallback pre-warm delay before Copilot starts. Ship does not directly manage Engram, but its isolated-worktree path and workspace-local MCP environment expose the defect.

Stage route: high-priority bug; read-only investigation/spike completed with proceed/high confidence for the rejection chain and medium confidence for the exact operator-visible timing until Ship captures runtime evidence. Chosen direction is secure worktree support plus fail-bounded startup; fail-fast-only, primary-checkout pinning, and removing pre-warm without root-cause repair were rejected.
