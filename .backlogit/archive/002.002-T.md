## Description

Define `BacklogNode`, `BacklogEdge`, `BacklogEdgeType`, and `BacklogIndexResult`
structs in a new module separate from the existing `backlog.rs` (which is actively
used by hydration/dehydration for SpecKit models).

## Scope

- `src/models/backlog_graph.rs` (new)
- `src/models/mod.rs` (add `pub mod backlog_graph;`)

## Implementation

- `BacklogNode { id, title, kind, status, labels, file_path, content_hash }`
- `BacklogEdge { from_id, to_id, edge_type }` (edge_type: parent_of, depends_on, references)
- `BacklogEdgeType` enum: `ParentOf`, `DependsOn`, `References` with `as_str()`
- `BacklogIndexResult { nodes: Vec<BacklogNode>, edges: Vec<BacklogEdge>, records: Vec<BacklogContentRecord> }`
  where `BacklogContentRecord` mirrors `ContentRecord` but targets the dedicated
  `backlog_content_record` CozoDB relation (separate from generic `content_record`)
- Existing `backlog.rs` models remain untouched

## Tests

- `tests/unit/backlog_graph_models_test.rs` (3 scenarios):
  construct structs, serialize/deserialize, verify edge type string representation

## Acceptance Criteria

- Models derive `Debug, Clone, Serialize, Deserialize`
- Edge types have consistent `as_str()` representations
- Existing `backlog.rs` models remain unchanged and functional
- `cargo test` passes
