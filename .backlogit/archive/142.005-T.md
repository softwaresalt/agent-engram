Plan unit F19 - canonical tool descriptor schema. Define one authoritative descriptor per tool in `src/tools/capabilities.rs`. Each descriptor declares its method/workflow name, capability class, schema, supported surfaces (`direct_ipc`, `cli`, `stdio_mcp`), read-server availability, and input ownership.

This descriptor registry becomes the single source from which the MCP catalog (F22), the CLI surface (F23), the dispatch capability gate (F21), the read-input inventory (F24), and the cross-surface parity matrix (F54) are all derived. F19 positively declares the three supported surfaces and has no dependency on HTTP/SSE transport deletion.

Execution posture: test-first.

<!-- BEGIN:acceptance-criteria -->
- Every tool has exactly one descriptor; no tool is reachable without one.
- Each descriptor declares method/workflow, capability class, schema, supported surfaces, read-server availability, and input ownership.
- `_health` is declared direct-IPC liveness only.
- `_shutdown` is declared as capability class Control.
- `doctor --smoke` declares a non-destructive readiness workflow in ReadServer mode.
- `get_retrieval_eval_report` stays MCP-only; no CLI surface is added without a separate approved requirement.
- A completeness contract test fails when a tool exists without a descriptor.
<!-- END:acceptance-criteria -->
