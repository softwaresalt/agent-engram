<!-- BEGIN:description -->
Harden the daemon's coalesced pending-sync drain (PR #293 review). Two gaps: (B1) background_db_hydration's cancellation path (lifecycle.rs ~248) and DB-connect-failure path (~261) call finish_indexing() WITHOUT drain_pending_sync, so a request queued with companion gate bits (pending_sync_revalidate / pending_sync_backfill_python, set in write.rs ~283-289) is left sticky and can leak into a later unrelated routine sync — spuriously triggering a heavy revalidate/backfill pass. (B2) drain_pending_sync (lifecycle.rs:389) runs once; a re-arm during the drain re-sets pending_sync (~433) and relies on an unspecified 'next finish_indexing caller', so a queued request can stall. Single width: daemon lifecycle / sync-queue state machine (src/tools/lifecycle.rs + src/tools/write.rs). Distinct from 103-F code-graph reconciliation and from the 015-D daemon-index non-persist/IPC spike (different defect, same width).
<!-- END:description -->

<!-- BEGIN:dod -->
- Companion state cannot leak past its owning request on any lock-release path; drain loops to completion on re-arm (bounded).
- RED regression tests (cancel leak, DB-fail leak, single-shot stall) fail pre-fix and pass post-fix.
- Existing lifecycle tests + recall suite green; ordered gates green (Ship-executed).
<!-- END:dod -->

<!-- BEGIN:goals -->
- Every finish_indexing lock-release path (normal, cancel, DB-fail) either drains or atomically clears ALL companion state together; no companion bit outlives its pending_sync.
- Cancellation/DB-fail paths CLEAR (atomic) rather than execute a heavy sync against a torn-down generation; normal completion LOOP-drains to completion (bounded).
- Preserve the write.rs publish-order invariant (companion bits before pending_sync); no happy-path behaviour change.
<!-- END:goals -->
