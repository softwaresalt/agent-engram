# CLI-only daemonless index population — duplicate of shipped 045-F / 030-S

## Problem Frame

<!-- BEGIN:problem-frame -->
Stash 0E042A84 (high, feature) requests a CLI command that populates the engram code-graph index directly, without starting the daemon/MCP server: open the embedded DB, run the workspace index pipeline, persist to .engram/, and exit — motivated by daemon-startup timeouts. Mandatory research grounding over the real src/ tree shows this capability ALREADY EXISTS and is SHIPPED. `engram index --direct`, `engram sync --full --direct`, and `ENGRAM_DIRECT=1` all bypass the daemon: run_direct_sync() (src/cli/direct.rs) acquires the DaemonLock for mutual exclusion, connects to the embedded CozoDB, calls the SAME service function the daemon uses (index_workspace_with_progress / sync_workspace_with_progress in src/services/code_graph.rs), persists to the resolved data dir (.engram/ via resolve_data_dir), emits a JSON-RPC 2.0 envelope with field-for-field parity, and exits on completion. Registered as clap subcommands in src/bin/engram.rs (Index{direct}, Sync{full,direct}) and dispatched via src/cli/commands/indexing.rs. NOTE: the stash text says 'SurrealDB' but the real backend is CozoDB (cozo_backend); there is no SurrealDB in the tree.
<!-- END:problem-frame -->
