## Description

Single release branch and PR producing the **`v0.3.0-rc.1` dogfood prerelease** from `main` at `bdda5aac8e6326d646e3b30d3144e4349db770a9`.

Covering feature: **`139-F`**.

### Operator decision encoded in this shipment

Create `v0.3.0-rc.1` now for dogfooding. Do **not** represent it as stable. Stable `v0.3.0` remains blocked on server reliability work (`002-SP`).

### Approval boundary (NON-NEGOTIABLE)

The operator approved **staging and building** this release unit. That is **not** approval to bypass PR merge policy.

| Gate | Ship may proceed unaided | Requires explicit operator approval |
|---|---|---|
| G1 — prepare release branch, commit, open PR, drive CI green | Yes | — |
| G2 — merge the PR to `main` | No | **Yes** |
| G3 — create/push tag `v0.3.0-rc.1`; publish or edit the GitHub Release | No | **Yes** |

If the operator is unavailable at G2 or G3, Ship **stops and leaves the PR open**. `main` merged-but-untagged is an explicitly safe resting state, not a failure.

### Hard prohibitions for this shipment

1. Do not run `cargo release --execute` in any form (`release.toml` has `push = true` + `allow-branch = ["main"]`; it would push commit and tag straight to `origin`, bypassing PR review and tripping `detect-direct-push.yml`).
2. Do not modify `release.toml`.
3. Do not modify `002-SP`, `128-F`, or `129-F` — they are unrelated queue artifacts.
4. Do not implement daemon-readiness / Cozo cold-start remediation. Do not change the readiness timeout anywhere, for any reason.
5. Do not upgrade `rmcp` or any MCP protocol constant.
6. Do not add `x86_64-apple-darwin` to the build matrix.
7. Do not bump `crates/powerbi-tmdl-parser`; do not run a broad `cargo update`.
8. Do not delete or re-point the `v0.2.0` tag or release.
9. New defects discovered go to the **stash**, not into this shipment.
