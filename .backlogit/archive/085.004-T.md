<!-- BEGIN:acceptance-criteria -->
- `find_powerbi_nodes_by_name` resolves a Power BI node by name (kind/source_path optional), returning candidates on ambiguity like the code path.
- `ImpactAnalysisParams` gains an additive, optional `powerbi_node_id` stable root selector so a caller can pin exactly one candidate returned by `find_powerbi_nodes_by_name`; when supplied it bypasses name resolution. Existing name-based calls are unchanged (back-compat).
- `impact_analysis` on a Power BI column returns an additive `powerbi_neighborhood` computed by an EDGE- and NODE-KIND-AWARE traversal — a plain single-direction incoming BFS is insufficient (it would pull the column's owner table/model in via incoming `pbi_contains`, or, if `pbi_contains` is excluded outright, leave page/report unreachable from visuals): it follows dependency edges (`pbi_uses_field`, visual->measure) plus `pbi_contains` ONLY onward to dependents (visual->page->report), yielding dependent measures and onward visuals/reports with `root_kind = powerbi_entity`, and EXCLUDING the root's owner table/model.
- A code-symbol root returns `root_kind = code_symbol` and NO `powerbi_neighborhood`; all existing fields unchanged.
- Contract test asserts the additive response shape + root_kind; integration test indexes the P3 multi-file fixture and asserts blast radius over a column surfaces its dependent measures/visuals/reports AND a NEGATIVE assertion that the column's owner table and model are EXCLUDED from `powerbi_neighborhood`.
- Disambiguation tests: a same-model duplicate column name and a code-symbol-vs-Power BI name collision each resolve to exactly one root via the `powerbi_node_id` selector.
- clippy pedantic clean; no CozoDB schema change.
