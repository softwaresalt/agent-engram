## Summary

<!-- BEGIN:summary -->
Reviewed the impl-plan that stops wasting GitHub Actions minutes by skipping the
single CI `build` job (fmt/clippy/test/audit) on doc/backlog-only PRs and pushes
via a `paths-ignore` trigger filter on `.github/workflows/ci.yml`. The plan is
grounded in the live workflow (single `build` job, `push`→main + all
`pull_request`, no existing path filter) and in the required-check spike, which
**definitively established that `build` is NOT a required status check** (ruleset
`PR-Required` id 12812291 enforces review + copilot-review only; PR #200 — a
backlog-only PR — ran a 3m14s build then merged with `REVIEW_REQUIRED`/`--admin`).
Because no status check is required, the stash's "required-check pending-forever"
gotcha does not apply, and a plain `paths-ignore` is the minimal safe mechanism.
Coverage on code PRs is structurally preserved by `paths-ignore` all-match
semantics (a single non-ignored code file re-arms the full workflow). Width is
isolated to one workflow file. **Disposition: ACCEPTED for harvest.**
<!-- END:summary -->

## Findings

<!-- BEGIN:findings -->
- **F1 (crux resolved):** The design-deciding question — is `build` a required
  status check? — is answered with primary evidence: `gh api .../rulesets/12812291
  --jq '.rules[].type'` and `.../rules/branches/main` return
  `deletion, non_fast_forward, pull_request, copilot_code_review, update` with
  **no `required_status_checks`**; classic protection is 404; PR #200 corroborates
  (backlog-only PR built for 3m14s, merged `REVIEW_REQUIRED`). The stash's core
  assumption is corrected. Grounding is conclusive — spike over experiment was the
  right call.
- **F2 (coverage cannot be weakened, resolved):** `paths-ignore` skips a run only
  when **every** changed file matches an ignored pattern; one code file re-arms the
  entire workflow. Code PRs therefore keep the FULL unchanged
  `--no-default-features --features cozo-backend,embeddings --all-targets`
  fmt→clippy→test→audit. Verified against GitHub path-filter semantics and pinned
  in the DoD (verification steps 2–3, incl. a mixed doc+code PR).
- **F3 (path set correct + tight, accepted):** Ignore set
  `.backlogit/**, docs/**, **/*.md, .autoharness/**` catches exactly the observed
  waste (067-S..070-S closures, spikes, unblocks all live under these). Bias is to
  over-run: `**/*.rs`, `Cargo.toml/lock`, `*.toml`, `.github/workflows/**`,
  `scripts/**`, `examples/**`, `src/**`, `crates/**` are deliberately NOT ignored
  and re-arm CI. No compiled/tested markdown exists, so `**/*.md` is safe.
- **F4 (rejected alternative sound, accepted):** The PR-title `if:` conditional is
  correctly rejected — fragile/bypassable, and a job skipped via `if:` is no safer
  than `paths-ignore` if `build` ever became required (both fail to post the
  check). `paths-ignore` strictly dominates by deciding on changed-file content.
- **F5 (future-coupling guardrail, accepted):** The plan documents the one real
  future hazard — if `build` is promoted to a required status check, `paths-ignore`
  will hang doc-only PRs on "Expected — Waiting for status" — and prescribes the
  companion always-passing job (same check name, inverse path filter) as the
  contingency, with an in-file `ci.yml` comment + snippet, **not** implemented now.
  Correct minimal-change posture.
- **F6 (scope guard explicit, accepted):** Step 5.5 guard is unambiguous. `release.yml`
  is tag-triggered and independent → correctly OUT of scope; broader CI redesign,
  coverage weakening, and any ruleset change are OUT and must spawn new items.
- **F7 (blast radius LOW, no plan-harden, accepted):** Single workflow file;
  additive trigger filter; no step/flag/job-name change; no action re-pin;
  ci-security SHA pinning + least-privilege `permissions: contents: read`
  preserved. Not multi-family, not schema/CLI-distribution — no `plan-harden` pass
  warranted. The genuine hazard (a path filter hiding a code change) is prevented
  by all-match semantics and probed by the verification plan.
- **F8 (decomposition, accepted):** One task, single width (CI/workflow only), no
  mixing with Rust/schema/CLI, comfortably under the 2-hour rule. Verification is
  folded into the task DoD (Ship executes the test PRs). Over-decomposition
  correctly avoided.
- **F9 (no-downstream-dependency check, accepted):** Confirmed only `ci.yml` and
  `release.yml` exist; nothing gates on a CI `push`-to-main success (release is
  tag-triggered), so skipping CI on doc-only pushes to `main` has no downstream
  consumer. No hidden coupling.
<!-- END:findings -->
