  against source. Bug 1: `start_column` (:523) uses `parse_identifier(rest)` and
  swallows `= <DAX>`; `parse_measure_declaration` (:920) is the exact mirror

  `trimmed.contains(':')`, consumed by `should_finish_measure_capture` (:627) and
  `capture_measure_body_line` (:645). No ambiguity in the fix sites.
- **F2 (test-first, resolved):** The harness pins the buggy output. Each task
  flips its pinned assertion(s): 070.001-T → `s_ptm_24…` (:368) +
  `s_ptm_28…` (:462); 070.002-T → `s_ptm_25…` (:397). The aggregate
  `differential_gate_counts()` (~:546, `heuristic_bugs == 2`) + module-doc delta
  table are reconciled as each bug lands (2→1→0). Correctly called out in both
  task specs.
- **F3 (S-PTM-28 propagation, resolved):** The downstream ingestion assertion
  flips purely from the parser name-split — adapter (`powerbi_tmdl.rs:105`) flows
  `name` through unchanged, so no adapter change is required. Verified.
- **F4 (additive surface, accepted):** New `TmdlColumn.expression` is additive
  (crate has no serde; `Default` → `None`); no field renamed/removed. Surfacing
  the expression onto `PowerBiColumn` is correctly held OUT of scope.

  is a serialization edge (shared `differential_gate_counts` aggregate +

  Documented as such; dependency-ordered in 070-S.
- **F7 (blast radius, accepted):** LOW. Two localized heuristic refinements in one
  crate behind an already-safe boundary; additive model surface; no
