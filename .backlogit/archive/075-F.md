title: Indexing progress status + bounded embedding-backfill memory
updated_at: 2026-07-06T11:08:47.0814117-07:00
---

The daemon content-embedding backfill embedded all pending records in one unchunked ONNX call: it ran after the scan completed so scan_status.running was already false (no progress reported for a multi-minute phase), and the giant batch made the ort runtime allocate/retain ~15.7GB. Chunk the backfill, relay per-chunk progress into the existing scan_status channel, and bound the ONNX batch size so indexing always reports status and memory stays low.
