## Summary

<!-- BEGIN:summary -->
Reviewed the impl-plan fixing the PR #207 post-merge finding: `DaemonError::NotReady`
is a **shared** variant, and its `--direct` escape-hatch hint is misleading on the
respawn shutdown-wait path (`wait_for_daemon_exit`, `src/shim/lifecycle.rs:392-395`)
because the stuck daemon still holds the daemon lock, so `engram index --direct` is
rejected at `src/cli/direct.rs:73-84` ("daemon is already running (pid …); stop it
before using --direct mode"). The plan introduces a **distinct**
`DaemonError::ShutdownTimeout` variant with its own wire code
(`8010` / `DaemonShutdownTimeout`; does **not** reuse `8006`) and retargets **only**
the shutdown-wait deadline branch, leaving `NotReady` (with `--direct`) for genuine
startup timeouts (`poll_until_ready`, `src/shim/lifecycle.rs:457`). Grounded against
source: both call sites confirmed; only `to_response` is an exhaustive `DaemonError`
match (compile-enforced new arm — no silent drop); `8010` is the next free 8xxx
(`8009 = WATCHER_INIT_FAILED`); the new message is thiserror brace-safe and
`--direct`-free. Test-first coverage: shutdown message omits `--direct` (brace-free);
startup message retains `--direct`; wire-contract tests for **both** variants. Blast
radius LOW/additive (≤3 files: `errors/mod.rs`, `errors/codes.rs`, `shim/lifecycle.rs`);
`plan-harden` NOT warranted. **Disposition: ACCEPTED for harvest.**
<!-- END:summary -->

## Findings

<!-- BEGIN:findings -->
Source-verified checks (persona gate):
- **C-1 (verified):** `NotReady` is genuinely shared by two call sites with opposite
  semantics — startup `poll_until_ready` (`lifecycle.rs:457`) vs shutdown
  `wait_for_daemon_exit` (`lifecycle.rs:392-395`).
- **C-2 (verified):** `--direct` is impossible in the shutdown path — `direct.rs:73-84`
  returns `AlreadyHeld` while the stuck daemon holds the lock.
- **C-3 (verified):** Only the `to_response` match is exhaustive over `DaemonError`
  (`mod.rs:483-496`); callers (`lifecycle.rs:169-260`/`309-320`) propagate via `?`, so
  adding a variant is compile-enforced, not a silent drop.
- **C-4 (verified):** `8010` is the next free 8xxx code (`codes.rs:56-64` uses 8001-8009,
  `WATCHER_INIT_FAILED = 8009`).
- **C-5 (verified):** the new message is thiserror brace-safe and `--direct`-free (only
  `{timeout_ms}` interpolates; §4 test 1 asserts brace-free + `!contains("--direct")`).

Findings:
- **F1 (Medium, resolved):** A shared variant carrying two contradictory remediations
  is the root cause; the plan splits into a *distinct* `ShutdownTimeout` variant with
  its own code/name rather than a runtime branch on text.
- **F2 (Medium, resolved):** The `NotReady` external wire contract (`8006`) stays frozen
  — its arm is untouched, the new `8010` is additive, and §4 wire tests (kept) plus an
  optional literal-`8006` pin (closure F1) guard it.
- **F3 (Low, resolved):** thiserror would fail to compile on a stray `{`/`}` in the new
  hint; §3.1 restricts braces to `{timeout_ms}` and §4 test 1 asserts brace-free.
- **F4 (Low, resolved):** Adding a variant could silently fall through a match — but only
  `to_response` is exhaustive, so the compiler forces the new arm.
- **F5 (Low, resolved):** The startup path must *keep* the `--direct` hint; the existing
  `not_ready_message_points_at_direct` test is kept as the paired positive assertion.
- **F6 (Info, deferred):** Embedding the concrete stuck `pid` in the message would be
  more actionable, but `Option<u32>` renders awkwardly in a thiserror string; §6 Q1
  recommends `{timeout_ms}`-only phrasing, with pid enrichment as a follow-up nicety.
<!-- END:findings -->

## Decisions

<!-- BEGIN:decisions -->
- **ACCEPT** the plan for harvest. Zero gate-blocking (P0/P1) findings; LOW severity
  (misleading hint on a rare respawn path) but a real dead-end.
- Ship 074-S with manifest [072-F, 072.001-T] (feature first, then the task).
- Binding conditions carried to Ship:
  - **C1** — Retarget **only** the `wait_for_daemon_exit` deadline branch
    (`lifecycle.rs:392-395`) to `ShutdownTimeout`; leave `poll_until_ready` (`:457`)
    on `NotReady`.
  - **C2** — Do **not** change the `NotReady` arm in `to_response`, its message, code
    (`8006`), name (`DaemonNotReady`), or `{timeout_ms}` detail.
  - **C3** — The new `ShutdownTimeout` message MUST be brace-free and MUST NOT contain
    `--direct` or `ENGRAM_DIRECT`.
  - **C4** — The new code MUST be a fresh 8xxx constant (`8010`), mapped exhaustively;
    do not reuse `8006`.
  - **C5** — Keep scope to `errors/mod.rs` + `errors/codes.rs` + `shim/lifecycle.rs`
    (≤3 files). Out of scope: broader error-taxonomy refactor, `IpcError::Timeout`
    wording, `bin/engram.rs` help.
- Open items (non-blocking): Q1 pid-in-message (defer), Q2 pin literal `8006` in the
  NotReady wire test (recommend include), Q3 confirm `8010` (free).
<!-- END:decisions -->
