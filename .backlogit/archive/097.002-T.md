V5 [P1] — validate the trusted storage-authority prefix before it can bind a path lineage edge. Domain: lineage-model (single file, single function-family). Plan Unit V5.

PROBLEM. `LineageAuthorityContext::resolve_path` (src/models/lineage.rs L211) trusts each `storage_authorities` allowlist prefix VERBATIM: `uri_matches_authority` (L289) does a raw `starts_with` + boundary check and never validates the prefix shape. Prefixes enter unvalidated from `LineageConfig::to_authority_context` (src/models/config.rs L373). A misconfigured prefix such as `s3://` (empty authority), `://bucket` (empty scheme), or `s3://bucket/some/path` (has a path component) can therefore bind edges for arbitrary URIs, breaking the `scheme://authority`-only trust invariant (AR-01).

CHANGE. Add `fn is_valid_storage_authority(prefix: &str) -> bool` in src/models/lineage.rs requiring the `scheme://authority` shape: a non-empty scheme before `://`, a non-empty authority immediately after `://`, and NO path/query/fragment component (no `/`, `?`, or `#` after the authority). Apply it in `resolve_path` so a malformed allowlist prefix is SKIPPED (fails closed) before `uri_matches_authority` can bind an edge — i.e. filter the `.any(|prefix| …)` closure through `is_valid_storage_authority` first.

FILE TARGETS. src/models/lineage.rs only (new predicate + `resolve_path` call-site + tests in the existing `tests` module). Do NOT widen scope into config.rs beyond, at most, a pass-through doc comment.

ACCEPTANCE CRITERIA (test-first):
- AC1 (malformed rejected): a context whose storage allowlist contains `s3://`, `://bucket`, or `s3://bucket/path` resolves NOTHING for any URI (no edge bound through the malformed prefix).
- AC2 (well-formed preserved): a well-formed prefix `s3://bucket` still resolves `s3://bucket/data/file.parquet` to its canonical `path::` endpoint (no recall regression).
- AC3 (query/fragment): confirm `s3://bucket?x` and `s3://bucket#f` are rejected as authorities (P3 review finding).

FAIL-CLOSED INVARIANT. Tightens (never loosens) the storage trust check; no new trust is granted (013-D precision floor). SAME-FILE NOTE (build sequencing, NOT a logical dependency): shares src/models/lineage.rs with W2 (097.003-T) and X1 (097.006-T); Ship serializes same-branch edits, so no `blocks` edge is warranted between V5 and W2.

Harness-ready: RED negative/positive unit tests then GREEN via the predicate. No schema/API change. Parallel with V2/W2/W1/V4; feeds X1 version bump.
