Add the lineage WRITE PATH + freshness stamp in src/services/notebook_indexer.rs, split out of U4 per H1's 2-hour granularity rule; consumes the Vec<LineageEdgeCandidate> collected by U4a (095.006-T). Persist via the U1a' writers: FLATTEN each candidate to one directional lineage_edge per (target, source) pair (a multi-source statement persists multiple edges sharing the target — cycle-5 F3); then assemble edges FIRST and upsert ONLY the dataset_nodes that are endpoints of an emitted lineage_edge (node creation is EDGE-DRIVEN, never endpoint-driven — a standalone read/write endpoint with no counterpart edge writes NOTHING; fail-closed, PR #281 finding D1); write via upsert_dataset_nodes / upsert_lineage_edges / upsert_lineage_edge_evidence (one lineage_edge_evidence row per (edge, cell) keyed on chunk_index so the same edge in two cells is preserved, not overwritten — finding E1) — NEVER through ExtractedEdge / the code_graph consumer. Regardless of edge count — INCLUDING a ZERO-lineage notebook — call upsert_lineage_index_state(notebook_path, CURRENT_EXTRACTOR_VERSION) UNCONDITIONALLY AND AS THE FINAL WRITE for the notebook — issued ONLY AFTER every node/edge/evidence upsert for that notebook has succeeded (an ORDERING constraint on the EXISTING calls; ZERO new functions) — via the U1a" helper for every EXTRACTED notebook, so a zero-lineage notebook is hash+version SKIPPED on the next run instead of being re-extracted every time (AR-03; the version-fingerprint skip predicate itself is U4b). Because the stamp is LAST, a failure in ANY earlier write leaves the notebook UN-stamped so it re-extracts on the next run (partial-failure recovery; the scope-delete makes re-extraction idempotent — AR-28); a stamp written BEFORE a failed graph write would let U4b's skip predicate MATCH and freeze a partial graph forever, so the stamp MUST NOT be issued early. On re-index of a CHANGED notebook, call delete_lineage_by_scope(notebook_path) BEFORE re-upsert (mirror index_notebook_source -> delete_content_records_by_scope at notebook_indexer.rs:98,164) so stale evidence (all cells) and orphaned edges are GC'd while still-evidenced datasets survive. NOTE: content-hash SKIP for UNCHANGED notebooks (notebook_indexer.rs:153-156) and whole-notebook DELETION cleanup (sweep_deleted_notebook_files, notebook_indexer.rs:238-263) are handled by U4b (095.009-T), not here. Tests: a cell containing ONLY a bare read (spark.table("c.s.t") with no downstream write) produces ZERO dataset_nodes and ZERO edges (edge-driven, finding D1); a MULTI-SOURCE candidate (a CTAS reading two tables) persists TWO directional lineage_edges sharing the write target each with its own per-cell evidence, and re-indexing a CHANGED notebook with one lineage cell removed drops exactly that cell's edge/evidence (cycle-5 F3); a ZERO-lineage notebook still stamps lineage_index_state and is SKIPPED (not re-extracted) on the next same-version run (AR-03).
