Plan unit F00 - test-manifest registration foundation. This repository auto-discovers no integration tests: `tests/` contains only `contract/`, `fixtures/`, `helpers/`, `integration/`, and `unit/`, so every target is declared explicitly and root `Cargo.toml` already carries 219 `[[test]]` blocks. Create the 49 new placeholder harness files this plan introduces, then append their 49 `[[test]]` blocks to root `Cargo.toml`, so every downstream unit writes into an already-registered target and never edits the root manifest.

This unit exists to close a false-GREEN failure mode: a nested harness that is never registered is inert, so its RED step would silently pass. It replaces implicit unordered co-ownership of the root manifest by ~30 units with a single owner.

Execution posture: structural enabler, build-verified. Placeholders import nothing from `engram`, so the tree is GREEN at registration and no behavior change is bundled with the move.

- 49 new placeholder harness files exist: 19 under `tests/contract/`, 26 under `tests/integration/`, 4 under `tests/unit/`.
- Root `Cargo.toml` gains exactly 49 `[[test]]` blocks and no other edit.
- Naming follows the repository convention `name = "<subdir>_<basename minus _test>"`, `path = "tests/<subdir>/<file>_test.rs"`.
- Placeholder files are created before their blocks are appended (required intra-unit order; Cargo does not existence-check a declared target `path` at metadata time).

- `cargo test --test <target> -- --list` resolves for each of the 49 new target names.
- No pre-existing `[[test]]` block is modified or removed; removing `integration_connection` belongs to F46.
