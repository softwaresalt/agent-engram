# Daemon `engram index` cross-file singleton non-persist + CLI response hang — investigate-first spike

## Problem Frame

<!-- BEGIN:problem-frame -->
On a FRESH git workspace, plain `engram index` via the DAEMON leaves cross-file singleton calls edges (e.g. alpha->beta) staged/unresolved, AND the `engram index` CLI hangs on response while the daemon completes server-side. Static analysis THIS CYCLE CONTRADICTS the stash's suspected root cause (direct.rs:162 use_index=full||force routing index->sync): `engram index` routes to index_workspace on BOTH paths — daemon via run_index -> run_tool_timed("index_workspace") (cli/commands/indexing.rs), and --direct via run_direct_sync(full=true) -> use_index=true -> index_workspace. The index path DOES run the unconditional cross-file post-pass (code_graph.rs:1815). So direct.rs:162 is NOT the cause for `engram index` (full=true). The content-hash skip freshness landmine (compound doc 2026-07-20) explains the ALREADY-indexed no-op case, but NOT the FRESH-workspace non-persist. The real defect is on the DAEMON path (routing/commit) and/or IPC response completion — unproven, needs hands-on daemon reproduction. Two entangled symptoms across CLI + daemon + IPC layers.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Hypotheses to test in the spike: || H1 (commit boundary): the daemon index_workspace tool (tools/write.rs:113) commits symbols but the post-pass singleton resolution is not flushed/committed before the IPC response, or runs outside the persisted transaction. || H2 (IPC framing/backpressure): the daemon finishes the long index but the response frame is never sent / the CLI read blocks (ipc_server.rs response completion) -> CLI hang; edges MAY actually be persisted but the client never observes completion, so the operator concludes "not persisted." || H3 (daemon routing divergence): the daemon routes `engram index` through an event-debounce/sync path (daemon/debounce.rs) rather than a true full index, skipping the post-pass on the daemon path specifically (divergence from --direct). || H4 (staging left unresolved): a cross-file alpha->beta call is staged correctly but the post-pass is not invoked on the daemon path, so it stays staged.
<!-- END:options -->
