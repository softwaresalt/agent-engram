DAX reference edges (pbi_uses_field) are never materialized for pre-existing indexed workspaces after a DAX-capable upgrade, because incremental indexing hash-skips unchanged .tmdl files. VERIFIED 2026-07-14: compute_dirty_model_scopes (src/services/powerbi_indexer.rs L1218) hashes .tmdl content only; there is NO index-format-version fingerprint (no TMDL_DAX_INDEX_VERSION anywhere), so unchanged pre-DAX .tmdl files stay hash-skipped until next edited. 'engram index' calls index_workspace WITHOUT force (src/cli/commands/indexing.rs:60-103); the current workaround is a manual one-time 'engram index --force'. DURABLE FIX: fold an index-format-version fingerprint (TMDL_DAX_INDEX_VERSION) into the .tmdl content hash in compute_dirty_model_scopes AND the main indexing loop so a version bump forces reprocessing of otherwise-unchanged files; add a one-time migration/re-index path triggered on version change. TEST-FIRST ACCEPTANCE: (1) failing test first: workspace indexed at version N with .tmdl files, version bumped to N+1, re-index materializes pbi_uses_field edges WITHOUT --force and WITHOUT editing files; (2) same-version re-index still hash-skips unchanged files (no needless reprocessing); (3) fingerprint participates in the dirty-scope hash deterministically. IMPL NOTES: define TMDL_DAX_INDEX_VERSION constant; mix into the hash used by compute_dirty_model_scopes and the main loop; bump for the DAX-edge format. Single-width: DAX incremental indexing (powerbi_indexer.rs + indexing version constant). BLAST RADIUS: forces one-time reprocessing on upgrade (runtime-affecting; re-index cost) — monitoring/rollback note required (observe re-index duration; rollback = revert version bump).
