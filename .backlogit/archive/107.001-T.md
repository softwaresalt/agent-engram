Tests-only RED milestone from the reviewed 107-F plan. Extend the existing same-file ambiguity acceptance harness to reproduce the PR #301 qualified `python_local` caller-attribution gap. The harness must assert exact caller and target identity, not merely edge existence, and must exercise both full-index and incremental-sync producers before any production fix is applied.

<!-- BEGIN:acceptance-criteria -->
- RED first: extend only `tests/integration/same_file_shadowing_acceptance_test.rs`; do not change production code in this task.
- Full-index scenario: a Python file has duplicate top-level caller names and one provable function-local import call. Resolve exact function IDs and assert neither duplicate owns a canonical edge to the trusted target; the current first-match path must make this assertion fail for the expected wrong-origin edge.
- Incremental-sync scenario: introduce or change the same qualified call through sync and assert no staged provenance row is keyed to either duplicate caller; assert `same_file_ambiguous_dropped` is non-zero. The current first-match path must fail this assertion for the expected arbitrary staged row.
- Unique-caller control: the equivalent single caller still stages/resolves the exact canonical target in the applicable index/sync path.
- At most three deterministic scenarios; no sleeps, daemon, IPC, CLI, schema, or persistence-format changes.
- The harness compiles and its RED failures identify caller attribution, not fixture/setup errors.
<!-- END:acceptance-criteria -->
