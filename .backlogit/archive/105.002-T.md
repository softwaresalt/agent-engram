PR #297 Copilot thread, src/tools/lifecycle.rs:466 (drain_pending_sync_to_completion, 457-480). The bounded snapshot loop peeks has_pending_sync (:463), drains (:466), yields, re-peeks (:473). This narrows but cannot close the producer/consumer TOCTOU where a sync caller fails try_start_indexing while a drain owns the lock, is descheduled BEFORE publishing pending_sync, and resumes only AFTER the loop's final has_pending_sync peek returns false -- the request is then queued with no guaranteed finisher until the next index/sync/watcher tick. Snapshot polling cannot fully close it. Fix: a state-machine handoff -- the producer atomically registers intent that the lock-holder observes on lock RELEASE. Must be generation-aware (depends on R1/105.001-T). Pre-existing; mitigated today by periodic watcher drains (fail-mode is latency/stall, not permanent loss).

<!-- BEGIN:acceptance-criteria -->
- AC1 (RED FIRST, MUST FAIL/STALL pre-fix): a deterministic test reproduces the producer/consumer TOCTOU -- a sync caller fails try_start_indexing while a drain owns the lock, is descheduled AFTER the drain loop's final has_pending_sync peek (:473) but BEFORE publishing pending_sync -- and asserts a finisher is still guaranteed WITHOUT an external index/sync/watcher tick. Fails/stalls under the current snapshot loop.
- AC2 (GREEN): replace snapshot polling with an atomic producer->lock-holder handoff -- the producer registers intent (compare-and-set / queued-intent) that the lock-holder observes on lock RELEASE and drains; the queued request is guaranteed drained.
- AC3: bounded (no set/drain livelock; keep the max-iteration guard); happy-path invariant -- normal completion still drains exactly the queued request with its companion bits once.
- AC4: no lost-wakeup -- test BOTH interleavings (intent-before-release, intent-after-final-peek); the handoff is generation-aware so a handoff registered against a new generation is NOT wiped by an old-generation cancel-clear (seam with R1/105.001-T).
