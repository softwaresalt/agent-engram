# Python-only last-wins recall recovery for same-file duplicate defs (layers on 100-F)

## Problem Frame

<!-- BEGIN:problem-frame -->
100-F/FF7DE872 chose fail-closed (Option A, language-agnostic): it DROPS the direct edge on same-file duplicate top-level defs to guarantee no wrong-target edge (013-D). For Python, where the last def legally shadows earlier ones at module scope, recall could be RECOVERED by minting the edge to the effective (last) definition (source-order/last-wins) instead of dropping. Documented v1 non-goal in docs/architecture.md "Same-file duplicate-name resolution (FF7DE872)". This is a recall-recovery enhancement layered on the merged 100-F, LOW priority.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
Option A (Python-only last-wins recovery): at the direct-edge minting sites, when >1 same-file same-name candidate exists AND language==Python, resolve to the LAST def in source order (Python module-scope last-def-wins) instead of failing closed; keep Rust fail-closed (last-wins is unsound for Rust inline-mod-per-file). Requires function_ids to carry source order (line_start). || Option B (stay fail-closed permanently, close won't-do): accept the documented v1 non-goal; same-file duplicate defs are rare, recall loss negligible. || Option C (conditional last-wins): last-wins ONLY when the shadowed defs are provably module-level same-scope; fail closed on conditional/try-except redefinition where "last in source" != "effective at call site". Tighter correctness, more complex.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
DECIDED (2026-07-29): KEEP FAIL-CLOSED — do NOT build last-wins recovery now. Rationale: 013-D (no-false-edge) is the governing invariant and recall is a documented v1 non-goal, not a rollback trigger. Option B (blanket last-wins) is UNSOUND — non-linear redefinition (if/try/with, decorators, @overload stubs) means last-in-source != effective-at-call-site, and the shared Rust+Python resolver would mint NEW wrong Rust edges (inline-mod same-name distinct targets disambiguated by module path, not source order). Option C (Python-gated linear/@overload-aware last-wins, Rust unchanged) is sound but complex and precision-risky for a rare pattern; its proof + adversarial-corpus burden is disproportionate to the low-frequency recall recovered. function_meta already carries line_start, so a future Option C is NOT blocked by missing data — deferring costs nothing structurally. REVISIT TRIGGER: measured recall loss on a real Python corpus (esp. @overload-heavy typed code) attributable to this fail-closed drop -> then pursue Option C with a mandatory zero-false-edge adversarial regression corpus. Decision doc: docs/decisions/2026-07-29-python-last-wins-recall-recovery-decision.md. PARK/ARCHIVE this deliberation; no shipment.
<!-- END:chosen-direction -->
