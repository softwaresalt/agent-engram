Install ONE outer wall-clock deadline covering the entire pre-readiness region, and disarm it through ONE stable read-only readiness-observation seam. Absorbs hardening constraint H12 and owns gate G9. This leaf installs, observes, and disarms only; the termination behaviour it triggers is owned by 143.003.002-ST, so this leaf never terminates a live process and is NOT gated on CP-3.

AC1 (ARMING POINT): the watchdog is armed at the earliest point in daemon entry at which a timer can run - before admission, before prepare_branch_owner, before IPC bind, and before the file watcher starts. A test asserts the arming point precedes all four, and a daemon stalled in admission/prepare_branch_owner still observes the deadline. This daemon has previously hung BEFORE the IPC listener bound, so a watchdog armed inside or after connect_db would leave the actual stall sites uncovered.
AC2 (SINGLE OUTER DEADLINE): the budget is one outer wall-clock deadline, not a per-phase budget. A test asserts that N slow phases summing under the budget do not fire it, and one slow phase exceeding it does.
AC3 (DEFAULT AND MARGIN): the default budget is 15 minutes (decision D13, PROVISIONAL), sourced from a named constant with the margin rationale in a doc comment, and re-validatable against 144.001.002-ST measured data once that data exists.
AC4 (GATE G9): the ENGRAM_READY_TIMEOUT_MS default is UNCHANGED. A regression test pins the current default constant to its recorded value and fails if the startup budget is conflated with it. The watchdog budget is a SEPARATE knob.
AC5 (SIGNAL ONLY): expiry raises an internal signal only; this leaf performs no process termination.

AC6 (ONE STABLE READINESS-OBSERVATION SEAM, NON-NEGOTIABLE): the watchdog observes readiness through EXACTLY ONE read-only readiness-observation seam. That single seam MUST serve both (a) the CURRENT managed-daemon mode and (b) the FUTURE 138-S separate read-server mode. The seam is specified by its OBSERVABLE CONTRACT - "has this startup attempt published readiness yet" - not by a concrete call site, so introducing read-server mode requires NO second observation path and NO fork in the watchdog.
AC7 (READ-ONLY AND NON-REFRESHING, NON-NEGOTIABLE): observing readiness through the seam MUST NOT write ReadinessView, MUST NOT write or advance any 138-S-owned activation state, and MUST NOT acquire or refresh a 143.002-T useful-work lease. A test asserts that N readiness observations leave both the idle-TTL deadline and the outstanding-lease count unchanged. The measurement must not itself be the activity - this is the exact failure class the 2026-09-04 idle-TTL livelock taught.
AC8 (DISARM CONTRACT TESTS IN BOTH MODES): two contract tests prove disarm through the same seam - (i) MANAGED MODE: readiness publication in the current in-process managed daemon disarms the watchdog; (ii) ACTIVATION-GATED MODE: readiness observed behind the activation gate disarms the watchdog with IDENTICAL semantics, using the same seam and no extra observation path. A healthy startup that then runs longer than the budget never fires it in either mode.
AC9 (MANDATORY POST-138 COMPATIBILITY RECHECK): a recorded recheck of this seam against the AS-MERGED 138-S readiness architecture is REQUIRED before 138-S resumes and before 144-S is claimed. The recheck outcome - compatible, or seam change required - is recorded as a named 143-S closure obligation. A seam that silently diverges after 138-S lands reinstates the never-disarming or wrongly-disarming watchdog this leaf exists to prevent.
