AMENDED FIXED INPUT (supersedes the prior single-invariant fixed input; both parts fixed, neither alone sufficient; Part A CORRECTED 2026-09-16 by Correction 1 to Amendment 1 - the prior "retained root anchor" wording was withdrawn because a root-relative read still resolves mutable path components beneath the root; FURTHER CORRECTED 2026-09-16 by Correction 2 to Amendment 1 - containment moved from a separate raceable precheck into the resolution episode itself, and that containment requirement was RATIFIED 2026-09-17 AS AMENDMENT 2 of the same lock): PART A SAME-OBJECT BINDING WITH IN-EPISODE CONTAINMENT - each corpus read resolves its target by name in EXACTLY ONE RESOLUTION EPISODE producing one filesystem object (one episode counts resolutions, not syscalls: a capability traversal walking each component in sequence to produce a single object is one episode), and BOTH the read-time identity verification AND every byte of the content read are performed against THAT SAME already-opened object; after the verification point the read performs ZERO name-accepting filesystem operations across the transitive call graph (no re-open by pathname, no re-resolution of any component, and no handing of the pathname to a downstream consumer that re-opens it, including via a procfs-style synthetic name); verification must succeed before any content is released, and on mismatch the read fails closed with no pathname-based fallback. ADDED BY CORRECTION 2 AND RATIFIED 2026-09-17 AS AMENDMENT 2: THE SAME SINGLE RESOLUTION EPISODE THAT PRODUCES THE BOUND OBJECT MUST ITSELF ENFORCE WORKSPACE CONTAINMENT AS A REQUIRED PROPERTY OF THAT EPISODE - the episode must not traverse outside the workspace boundary, including the final component as resolved, and must fail closed if it would. Containment is a property of the TRAVERSAL, never of the object (an object has no location, only directory entries do, and the object at issue has entries on both sides of the boundary); no claim is made about where the produced object "is". A separately-performed containment check does NOT satisfy this requirement when its result is carried into the episode as a NAME (pathname, canonicalized string, or any value the episode must re-resolve) - such a check is raceable by construction; a result carried as a BOUND REFERENCE the episode resolves against and never re-accepts by name is not excluded, but binding a boundary reference is not itself the enforcement - the enforcement is the episode's refusal to traverse outside it. An additional containment check retained elsewhere is neither required nor forbidden but can NEVER be the enforcement. Boundary establishment is outside the episode count as a counting convention only, not a licence to re-resolve. FEASIBILITY ESCALATION, EVALUATED PER SUPPORTED TARGET TRIPLE ("supported platform" means TARGET TRIPLE, not cfg family - a guarantee established for one Unix target does NOT generalize to another): if on any single supported target no available primitive can deliver a FIXED PROPERTY of this input - containment as a property of the producing episode, containment ATOMIC WITH the production of the bound object (R9), OR PART B's OBJECT-DERIVED IDENTITY OBTAINED FROM THE BOUND OBJECT - the deliberation must escalate to the operator and fail closed for that target. The clause covers EVERY FIXED PROPERTY, not containment alone: Part B is as capable of being platform-infeasible as Part A, and an escape hatch for one and not the other would push the weaker property into a silent substitution. Delivering a property on one supported target does NOT discharge it on another, and no separately-performed check may be substituted and described as satisfying PART A OR PART B. ATTACKER CAPABILITY, STATED PER SUBCLASS (in-episode containment is NEVER INERT and no absence of attacker capability makes it unnecessary): the RACE subclass requires write access to ANY directory traversed by the read episode, INCLUDING directories inside the workspace that an agent writes to continuously, and on Windows this planting step is UNPRIVILEGED because directory junctions and other reparse points need no privilege, unlike symbolic links which require SeCreateSymbolicLink or Developer Mode; the UNTRUSTED-PATHNAME subclass requires NO attacker write at all (a caller-supplied relative path such as ../../outside/link-to-authorized-object produces R1b directly, with no race to win); the PRE-EXISTING-LINK subclass requires no write at read time (a symlink, junction, or reparse point already present in checked-out or extracted content redirects the episode on first traversal); and A2 and R4 redirect resolution with NO directory-write capability of any kind. In-episode containment is the required prevention for the R1b subclasses - race, untrusted-pathname, pre-existing-link - CONDITIONALLY and per the residual table; it does NOT close A2 or R4, which are listed for their capability profile and not as things containment prevents. Neither a workspace-root reference nor a parent-directory reference satisfies Part A. A retained full-path capability is permitted as a REALIZATION of Part A and as hardening of the open, never as an equivalent substitute, and only if the single object that traversal produces is the same object that is both verified and read. PART B OPAQUE PER-FILE IDENTITY EQUALITY - retained in full and INDEPENDENTLY REQUIRED, unchanged by Correction 2 (Part A binds which object is read consistently and that the traversal stayed contained, never which object is authorized): read-time identity must EQUAL the opaque stored authorized identity, compared for equality and never reconstructed, parsed, or re-derived, and remaining inside the workspace is not sufficient. PRECISION REQUIRED BY EVIDENCE: the identity must denote the OBJECT, not a name for it - both the stored and the read-time identity must be obtained FROM THE BOUND OBJECT rather than by resolving a pathname, with derivation symmetry required; a canonicalized path string is a name and is invariant under rename-over, hardlink substitution at the authorized path, and mount overlay. This constrains PROVENANCE, not type. CONTAINMENT IS NECESSARY AND NOT SUFFICIENT; identity is not a substitute for containment any more than containment is a substitute for identity, and generation 1's rule is NOT inverted. What Correction 2 changed is WHERE containment lives: a required property of the resolution episode, not a precondition evaluated before it. ROOT-CAUSE EVIDENCE (preserved and strengthened): an ancestor directory replaced by a symlink redirecting elsewhere inside the workspace must be rejected.
