# cozo 0.7 → 0.8+ major bump feasibility (clear lz4_flex RUSTSEC-2026-0041)

## Problem Frame

<!-- BEGIN:problem-frame -->
102-F/093-S cleared 9/10 baseline cargo-audit vulnerabilities, leaving ONE accepted-with-rationale advisory: RUSTSEC-2026-0041 (lz4_flex 0.10.0). Chain: engram -> cozo 0.7.6 -> swapvec 0.3.0 (NON-optional cozo dep, cannot be feature-dropped like the requests->minreq path) -> lz4_flex 0.10.0. swapvec 0.3.0 pins lz4_flex ^0.10; the fix (>=0.11.6) is a 0.x breaking bump the range rejects. No in-range fix at cozo 0.7.6 (Cargo.toml:31 pins version=0.7). Clearing it needs an upstream cozo/swapvec release using lz4_flex >=0.11.6, OR a cozo 0.8+ major bump with graph-backend blast radius (storage-sqlite/storage-sqlite-src/graph-algo API surface). Exposure is low: swapvec is cozo internal on-disk spill (trusted round-trip, not attacker-controlled); CI audit is non-blocking (continue-on-error).
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) Take the cozo 0.8+ major bump now — clears the advisory but UNKNOWN/unscoped API delta across storage-sqlite/graph-algo + thousands of lines of CozoScript in cozo_queries.rs; large blast radius, cannot honestly bound to <=2h or a single width. || B) Wait for an upstream in-range fix (patched lz4_flex 0.10.x backport, or a cozo 0.7.x re-pinning swapvec) — zero blast radius, clears for free, contingent on upstream. || C) Hold at accepted-with-rationale (status quo) — advisory documented + accepted (low exposure, non-blocking CI); zero work/risk.
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
DEFER (Option C now, gated toward Option B; Option A only after a scoped spike). No urgency (accepted-with-rationale, low real exposure, non-blocking CI). Option A's blast radius is unproven — before any impl plan a SHIP/runtime-executed spike must: enumerate engram's cozo public-API touchpoints; build a throwaway branch bumping cozo to latest 0.8+ and capture the compile-error + CozoScript/graph-algo/storage-src delta; VERIFY the 0.8+ line actually re-pins swapvec/lz4_flex to a patched version (else Option A does not even clear the advisory); check bundled-SQLite on-disk/cold-restart compatibility; and estimate a >=2h-per-unit width-isolated decomposition. Hands-on branch is out of Stage role scope (needs cargo build) — recorded here, deferred. Prefer Option B opportunistically if an upstream fix lands first. NOT scheduled into a shipment this cycle. Full write-up: docs/decisions/2026-07-29-cozo-0_8-major-bump-feasibility-deliberation.md.
<!-- END:chosen-direction -->
