Implement the DaemonVerified, HealthVerified, CliProbeVerified and McpProbeVerified stages: confirm the daemon picked up the expected generation through request-entry reconciliation, then verify health and representative CLI and MCP reads before the machine may report `Succeeded`.

<!-- BEGIN:acceptance-criteria -->
- DaemonVerified confirms the daemon activated the EXPECTED generation revision, not merely any generation.
- HealthVerified confirms the daemon reports healthy.
- CliProbeVerified performs a representative CLI read and asserts success plus provenance.
- McpProbeVerified performs a representative stdio MCP read and asserts success plus provenance.
- Verification relies on request-entry reconciliation; NO generation-control endpoint is called (R48).
- `Succeeded` is reachable only when all four verifications pass within the shared deadline.
<!-- END:acceptance-criteria -->

<!-- END:implementation-notes -->

<!-- BEGIN:verification -->
1. Success-path assertion: all four verifications pass and the machine reports `Succeeded`.
2. Negative assertion: a daemon serving an older revision does NOT reach `DaemonVerified`.
3. Assertion that no control/reload endpoint is invoked.
