## Summary

Fix S-PTM-24 (calculated-column mis-scoping) in the safe TMDL parser. For a
calculated column `column <name> = <DAX>`, the parser currently swallows the
whole `= <DAX>` into the column name and drops the expression. Split the
declaration on the first top-level `=` and capture the DAX into a new additive
`TmdlColumn.expression`, mirroring exactly how measures already work. Test-first:
flip the pinned buggy assertions to the correct expectation, then make the parser
change green.

## Ground truth (already read)

- `crates/powerbi-tmdl-parser/src/lib.rs`
  - `TmdlColumn` struct :78 (derives `Default`; **no serde** — add field is purely additive).
  - `start_column` :523 — currently `name: parse_identifier(rest)` swallows the whole rest.
  - `parse_measure_declaration` :920 — the exact pattern to mirror: `rest.splitn(2, '=')` → `(name, Option<expression>)`.
  - `PendingMeasureBody` :192 + `capture_measure_body_line` :645 + `should_finish_measure_capture` :627 — the multiline-body machinery to mirror for the `column X =` / next-line-body form.
- `src/services/powerbi_tmdl.rs` :105 — `PowerBiColumn` mapping flows `name: column.name` through unchanged; once the parser yields `name: "Margin"`, S-PTM-28's name assertion passes automatically (no adapter change required).
- Finding: `docs/decisions/2026-07-04-tmdl-eval-gate-finding.md` (S-PTM-24 row + fix localization).

## Implementation notes (for Ship, not done here)

1. Add `pub expression: Option<String>` to `TmdlColumn` (:78) — additive; `Default` → `None`.
2. Add a `parse_column_declaration(rest)` mirroring `parse_measure_declaration` (:920): `splitn(2, '=')` → `(name, Option<expr>)`; use it in `start_column` (:523) instead of `parse_identifier(rest)`.
3. For the multiline form (`column FullName =` with the DAX on the following deeper-indented line), mirror the `PendingMeasureBody` mechanism (a pending column-expression body capture that appends deeper-indented lines until the property/declaration/indent boundary), so `expression` holds `[FirstName] & " " & [LastName]`.
4. Do NOT surface the expression onto `PowerBiColumn` (adapter) — that is a model-richness addition and is OUT of scope; the parser-level capture is sufficient to flip the pinned assertions.
