Capture workspace + config atomically in the get_workspace_status handler to remove a capability-discovery data race. VERIFIED 2026-07-14: src/tools/lifecycle.rs reads retrieval_eval_enabled from a config read (L515) taken separately from the workspace snapshot (~469); a concurrent set_workspace updates workspace + config in separate awaits, so status can pair one workspace's path/branch with another config's retrieval_eval_enabled. Fix: take a single atomic snapshot at handler start via snapshot_dispatch_context() (the pattern tools/eval.rs already uses) and read both workspace and retrieval_eval_enabled from it.
