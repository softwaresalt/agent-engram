STARTUP-ATTEMPT IDENTITY AND COMPLETE PHASE ATTRIBUTION. Without attempt identity, records from concurrent or successive attempts are not separable and no single attempt can be classified.

AC1 (ATTEMPT IDENTITY ON EVERY RECORD, ALL SIX FIELDS): every record carries (i) a UNIQUE STARTUP-ATTEMPT ID generated once per attempt, (ii) WORKSPACE identity, (iii) BRANCH, (iv) GENERATION ID or an explicit none/unresolved marker, (v) IPC ENDPOINT, and (vi) PROCESS-START IDENTITY - the process ID TOGETHER WITH its start time, so a recycled PID is never mistaken for the same process.
AC2 (MONOTONIC SEQUENCE): each record carries a monotonic sequence number within its attempt. Record order is recoverable from the sequence ALONE, independently of timestamp resolution or clock adjustment. A test asserts strictly increasing sequence and correct recovery under a deliberately coarse or adjusted clock.
AC3 (COMPLETE PHASE SET, NONE OMITTED): phase_started/phase_completed pairs are emitted for the FULL set - admission, prepare_branch_owner, process_lock, file_lock, database_open, schema_bootstrap, readiness publication, hydrate_code_graph, detect_offline_changes, and the optional sync_code_graph. Omitting admission or prepare_branch_owner would leave a blind spot immediately before the only unbounded region, so a stall there would be indistinguishable from "the daemon never started". IPC bind and file-watcher start are RETAINED AS EXPLICIT ADDITIONS to this set if and only if they are measured; if they are not instrumented, that omission is recorded explicitly rather than left implicit.
AC4 (ATTEMPT SEPARABILITY): two interleaved startup attempts write records that are FULLY SEPARABLE by attempt ID. A test asserts no cross-attribution of any phase.
AC5 (READINESS PUBLICATION RECORD AT THE EXACT SITE): a durable readiness_published record is emitted at the exact point set_hydration_ready_for_generation is called in src/tools/lifecycle.rs::background_db_hydration.
AC6 (MID-STALL ATTRIBUTION): killing a daemon mid-bootstrap leaves durable evidence naming the phase it was executing, INCLUDING when killed during admission or prepare_branch_owner.

MEASUREMENT ONLY: this leaf adds observation. It changes no startup ordering, no readiness semantics, and no storage resolution.
