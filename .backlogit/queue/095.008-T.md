Document the v1 Spark-lineage feature: what it produces and its fail-closed boundaries. Cover: v1 emits lineage_derives_from edges for TABLES (3-part catalog.schema.table bound to trusted metastore authority) and PATHS (absolute URI bound to storage authority) ONLY; dataset_node.kind = {table, path}; the edge is ORIENTED from_id = written target -> to_id = read source (data flows source->target; the edge encodes derives-from — AR-05); dataset_node carries canonical fields only and per-notebook provenance lives in lineage_edge_evidence; a dataset_node is created ONLY as an endpoint of an emitted lineage_edge (edge-driven, never endpoint-driven — a standalone read/write with no edge produces no node; finding D1). Fail-closed drops (013-D, 0 false edges): 1-/2-part names, relative literals, f-strings / variable args, config/widget paths, a 3-part literal with NO trusted authority, unresolvable metastore/storage authority. Deferrals / limitations with DISTINCT rationale: temp-view lineage deferred = unrepresentable (Fork A, no durable node) — the ONLY view kind asserted fail-closed; PERMANENT (catalog) views are a documented v1 LIMITATION, NOT a fail-closed drop — v1 cannot distinguish a permanent view from a table (both are a 3-part name + authority), so a permanent-view ref is recorded as kind=table (future extension = a distinct view node kind + CREATE [OR REPLACE] VIEW DDL to label them precisely; AR-08); spark.sql(...) string-embedded SQL deferred from the Python path = scope-minimization (removed from the U2 whitelist; the equivalent CTAS/INSERT lineage is captured when written in a %%sql cell/U3; future extension = delegate the literal to extract_sql_lineage; finding D2). Cross-cell DataFrame propagation OUT (single-cell resolver only). Source/cell order (chunk_index) is metadata, NEVER an edge. Record the DECIDED %sql line-magic policy: %sql LINE-magic cells are EXCLUDED from v1 — only the %%sql cell-magic routes to U3 (AR-11). State the verdict is feasibility-only: product value is operator-asserted and empirical recall is the Fork A GO/NO-GO checkpoint (not a shipped guarantee). Document the retrieval surface: v1 adds NO new MCP tool — lineage is queryable via query_graph AFTER U8 extends its traversal + dataset_node resolution (there is no query_sql tool; PR #281 finding 7). Document the traversal DIRECTION (AR-06): outgoing / find_path from a TARGET reaches its SOURCES (upstream lineage); an INCOMING neighborhood from a SOURCE reaches its downstream CONSUMERS. Document the RELEASE ROLLBACK TRIGGER: any confirmed false lineage edge disables/reverts lineage indexing (the zero-false-edge invariant is the trigger); name the observation window + owner (PR #281 finding 8). Domain: docs (width-isolated). Blocked by U6 and U8. Plan Unit 7.
