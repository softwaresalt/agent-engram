Plan unit F50a, Slot-09a of the 142-F decomposition plan Revision 18 (`docs/exec-plans/2026-09-30-142-f-decomposition-plan.md`, section 4.3 split S-09 of `142.054-T`, created at assembly step 4 as placeholder `142.054a`; carries `142.054.001-ST`). Unit source: plan unit F50 in `docs/exec-plans/2026-09-02-separate-indexer-read-server-plan.md`, with the PA-2b guidance "F50 completion after PRE-6" in `docs/exec-plans/2026-09-26-142-f-launcher-preflight-command-plan.md`. Route (a-1). Execution posture: test-first. The harness-architect re-qualifies this task's F50 share on the slot's base tree; parked commits `c269fa79` and `41dd5081` are reference only.

Scope (this task's share of F50), in `crates/engram-indexer/src/preflight.rs`:
- The typed stage enum and transition table for Build -> Seal -> Publish -> DaemonVerified -> HealthVerified -> CliProbeVerified -> McpProbeVerified -> Succeeded, or a typed `Failed` naming the stage. Transitions are forward only; skipping a stage is unrepresentable.
- ONE deadline and ONE expected generation carried by the machine, not by individual stages.
- Fail-closed semantics: any failure yields `Failed`, never a degraded `Succeeded`. This supersedes the 118-S Guardrail 4 fail-open behavior: an agent session must not be able to begin with Engram degraded.
- Mock-driven cases in `tests/integration/preflight_gate_test.rs` (target `integration_preflight_gate`): success, failure at each of the seven stages (one table), and the single deadline. This task writes them as its RED cases at its own Step 2.

Not in this task: the Build, Seal and Publish stages of `ProductionVerifier` (Slot-09b, `142.079-T`); the four probe stages, the PA-2b real-chain cases and the crate-wide gates (Slot-09c, `142.054-T`).

- [054-T AC1; 054.001-ST AC2] The state machine is typed: the transition table permits only forward transitions, and an invalid or stage-skipping transition is unrepresentable rather than a runtime check.
- [054-T AC2; 054-T AC3; 054.001-ST AC3] Exactly one deadline spans the whole sequence (individual stages do not each restart it), and exactly one expected generation is carried through every stage; both are carried by the machine, not by individual stages.
- [054-T AC4; 054.001-ST AC4] Every stage failure produces a typed `Failed` variant naming the stage that failed.
- [054-T AC5] The machine is FAIL-CLOSED: any failure yields `Failed`, never a degraded `Succeeded`.
- [054-T AC6] `Succeeded` is reachable only after all seven stages verify.
- [054-T AC7] `tests/integration/preflight_gate_test.rs` covers success and a failure injected at each stage (mock-driven; the failure cases are one table).
- [054.001-ST AC5] The types compile clean under `-Dwarnings` and `clippy::pedantic`.
