Deferred follow-up from 091.016-T (PR #267 Copilot review). 091.016-T (Options 1+2) removed the blocking pre-pass reads (tokio::fs) and the duplicate canonical-context PARSE (hash-checked context reuse), but it did not remove the second file READ: the global unsafe-module pre-pass reads every Rust file once, and the main index and sync passes each read the same paths again. Eliminating the second read requires caching the pre-pass source bytes and having the main/sync pass consume that single snapshot instead of re-reading from disk. That same single snapshot also closes the pre-existing pre-pass/main-pass TOCTOU on the global unsafe_prefixes set: because prefixes and per-file contexts would then derive from one identical byte snapshot, a file that gains a #[path] or #[cfg] mod remap between the two reads can no longer leave the global prefix set stale (which today could emit a canonical edge that a fresh snapshot would suppress). The tradeoff is memory that scales with total workspace source size held for the duration of the index, so the cache must be drained per-file as the main pass consumes it and bounded against the max-file-size guard. The sync path only re-indexes changed files, so the snapshot reuse must be scoped to avoid holding all source for a partial re-index. Acceptance: no second file read on the canonical path for a full index; per-file source dropped after consumption (bounded peak memory); identical canonical edge output to the pre-091.016 baseline; the global-prefix TOCTOU regression fixture (a file gaining an unsafe mod remap between pre-pass and main read) passes; benchmarked read/parse reduction on a large workspace. Priority low: pre-existing behavior, correctness-neutral today, purely a performance and robustness enhancement.
