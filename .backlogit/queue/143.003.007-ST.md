RETRY-LEDGER ATTRIBUTION AND INVOCATION-SHAPE SEMANTICS. Split from 143.003.004-ST in Revision 3 so neither leaf carries more than four test scenarios. Depends on the ledger storage protocol existing first.

AC1 (EXACT-CHILD ATTRIBUTION): ONLY a termination of the child process THIS SHIM STARTED, carrying the 143.004.002-ST watchdog failure class, increments the counter. A crash, an operator kill, an unrelated exit, and a termination of a different workspace's daemon each leave the counter unchanged. Tested per case.
AC2 (RESET ON READINESS): the first startup that reaches readiness CLEARS the counter, so a workspace that recovers is not carrying stale failure credit.
AC3 (BOUNDED COOLDOWN): after a bounded cooldown the counter also clears, so three transient failures cannot wedge a workspace permanently. The cooldown duration comes from a named constant with recorded rationale.
AC4 (REPEATED CLI INVOCATIONS): N successive INDEPENDENT CLI invocations accumulate the count correctly across processes - the production shape that an in-process counter silently breaks.
AC5 (LONG-LIVED MCP SESSION): a SINGLE long-lived MCP session spanning multiple daemon terminations accumulates the count correctly. The two invocation shapes are asserted separately because they exercise different lifetimes and a fix correct for one can be wrong for the other.
