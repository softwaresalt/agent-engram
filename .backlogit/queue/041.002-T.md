## Description

Remove the fd-lock advisory lock in `connect_db`, the `run_script_busy_retry_mutable`
retry loop, and the `MUTABLE_RETRY_COUNT` / `MUTABLE_RETRY_EPOCH` atomics that
were added as SQLITE_BUSY mitigations.

Also owns the later 082-S / 086-F interim mitigations on the same shared paths:
`catch_busy_panic` + `open_db_with_retry` (+ `reopen_backoff` / `open_retry_jitter` /
`is_sqlite_busy_or_locked_panic`) in `connect_db` (086.002), and the `run_script_retrying`
routing of the `calls_edge` migrate/rollback `:replace` rewrites (086.001). Removal of these is
gated in TWO distinct steps — see Implementation.

## Scope

- `src/db/cozo_backend/mod.rs` (remove fd-lock in connect_db; remove catch_busy_panic +
  open_db_with_retry + reopen_backoff / open_retry_jitter / is_sqlite_busy_or_locked_panic — 086.002)
- `src/db/cozo_backend/schema.rs` (revert calls_edge migrate/rollback to direct run_script — 086.001)
- `src/db/cozo_queries.rs` (remove run_script_busy_retry_mutable and atomics)
- `src/services/metrics.rs` (remove retry metric tracking if present)

## Implementation

- Delete fd-lock acquisition logic from connect_db
- Delete run_script_busy_retry_mutable function
- Delete MUTABLE_RETRY_COUNT and MUTABLE_RETRY_EPOCH atomic counters
- Replace retry-wrapped calls with direct run_script calls
- Verify all tests pass without mitigations

### Two-step removal for the 082-S reopen mitigations (do NOT conflate)

1. Remove `catch_busy_panic` once cozo ≥ 0.8 returns an `Err` (no internal `unwrap`) for
   SQLITE_BUSY/SQLITE_LOCKED — this only changes the surface (panic → Err); the transient persists.
2. Remove the retries (`open_db_with_retry`, and the calls_edge migrate/rollback
   `run_script_retrying` routing) ONLY after verifying upstream ABSORBS the transient (a rapid
   sequential reopen no longer surfaces busy/lock). Cozo merely returning Err is NOT sufficient —
   the retry still guards startup. See
   `docs/compound/concurrency-issues/cozo-sqlite-busy-locked-reopen-panic-catch-unwind-2026-07-15.md`.
