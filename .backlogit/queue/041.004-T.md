## Description

Remove `cfg_attr(target_os = "windows", ignore)` annotations from integration tests
that were added as CozoDB SQLITE_BUSY workarounds. Also fix the separate Linux
`flush_state` race in `smoke_test.rs` (which is a test-sequencing issue, not CozoDB).
Redesign the rehydration test to verify rehydrated-only state before auto-index.

## Scope

- `tests/integration/smoke_test.rs` (remove Windows cfg_attr ignore AND fix Linux flush_state race by awaiting index completion before flush)
- `tests/integration/graph_vector_rehydration_test.rs` (remove cfg_attr + redesign)
- `tests/integration/concurrent_sessions_test.rs` (remove `#[ignore = "U015-FLK1"]` from s_cs4 test)

## Implementation

- Remove Windows cfg_attr ignore annotations targeting SQLITE_BUSY scenarios
- Fix `smoke_full_tool_chain_over_ipc` Linux ignore: the test calls `flush_state` before startup auto-indexing finishes → add a wait-for-index-complete step before flush (same pattern as other daemon tests). This is NOT a CozoDB bug — it's a test sequencing error
- Remove `#[ignore = "U015-FLK1: ..."]` from `s_cs4_concurrent_indexing_serialised_by_in_progress_flag` in concurrent_sessions_test.rs
- Redesign rehydration test: verify rehydrated-only state before auto-index
  completes (use a flag or timing gate)
- Ensure all three test files pass on all platforms (Windows, Linux, macOS)
