Deferred follow-up from 088-S (Unit B). The A6 migration reshapes function_meta to add canonical_path but does not backfill pre-existing rows, and the A8 forced re-index was removed as unsafe (symbol IDs are random UUIDs; re-parsing unchanged files would disturb the existing edge set). Result: an already-indexed workspace only gains canonical call edges for files re-parsed by a normal index/sync; pre-existing rows keep canonical_path='' (fail-closed via D4 — empty is never a match target, so no false edges, only under-reporting until reindex). Implement an ID-preserving backfill that recomputes canonical_path for existing function_meta rows WITHOUT changing their UUIDs, then re-runs the canonical post-pass, so existing workspaces gain full recall without a destructive reindex. Acceptance: existing workspace canonical edges materialize without UUID churn; no false edges; idempotent.
