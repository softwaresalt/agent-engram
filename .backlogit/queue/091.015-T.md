Deferred follow-up from 088-S (Unit B). The A6 migration reshapes function_meta to add canonical_path but does not backfill pre-existing rows, and the A8 forced re-index was removed as unsafe (symbol IDs are random UUIDs; re-parsing unchanged files would disturb the existing edge set). Result: an already-indexed workspace only gains canonical call edges for files re-parsed by a normal index/sync; pre-existing rows keep canonical_path='' (fail-closed via D4 — empty is never a match target, so no false edges, only under-reporting until reindex). Implement an ID-preserving backfill that recomputes canonical_path for existing function_meta rows WITHOUT changing their UUIDs, then re-runs the canonical post-pass, so existing workspaces gain full recall without a destructive reindex. Acceptance: existing workspace canonical edges materialize without UUID churn; no false edges; idempotent.

## Blocked — needs operator input on trigger/invocation design

The backfill *mechanism* above is technically feasible (ID-preserving recompute +
canonical post-pass, fail-closed). It is blocked on a product+performance decision the
operator must make: **when/how the backfill runs.** Candidate triggers —
auto-on-daemon-startup, an opt-in maintenance command, or folded into a force-sync —
each carry blast radius on large already-indexed workspaces (startup latency, CPU on
first bind, surprise reindex cost). This is the same area where the operator removed
the A8 forced re-index as unsafe. The recall gap is PERSISTENT, not self-healing: a
normal `engram index`/`sync` runs with `force=false` and hash-skips unchanged files
(`src/services/code_graph.rs:532-541`; `src/cli/commands/indexing.rs:99-104`), so
pre-existing rows keep `canonical_path=''` until a `--force` reparse (the forced
reparse removed as unsafe — it churns UUIDs and disturbs edges) or an actual per-file
content change. That persistence is exactly why an ID-preserving backfill is warranted;
it does not change the fact that the trigger/invocation design is the blocking open
decision. **Unblock decision:** operator chooses the trigger model; then this task is
immediately implementable. Rationale detail in
`docs/memory/2026-07-17/091-020-T-recall-denominator-memory.md`.
