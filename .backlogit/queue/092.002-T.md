Reader-side workspace+config atomicity follow-up to 092.001-T (writer-side). Two pre-existing background paths in src/tools/lifecycle.rs read the (workspace,config) pair non-atomically via separate snapshot_workspace()+workspace_config() awaits: background_db_hydration (~L336) and drain_pending_sync (~L397). Gemini concurrency review (086-S) flagged both as P2. Add a None-gating atomic reader on AppState returning Option<(WorkspaceSnapshot, WorkspaceConfig)> that acquires both read guards in the reader lock order and preserves skip-if-either-None semantics; migrate both background paths to it. Source: 086-S adversarial review C1/C2. See docs/closure/2026-07-17-086-writer-atomicity-closure.md.

<!-- BEGIN:acceptance-criteria -->
TEST-FIRST:
1. Add a non-vacuous test proving a concurrent bind transition (A->B) is never observed as a mismatched pair (workspace_i, config_j) with j != i by the background-reader path. The test MUST fail against the current separate-await reads (proves non-vacuity) and pass after the fix.
Then implement:
2. New AppState reader returns Option<(WorkspaceSnapshot, WorkspaceConfig)>, acquiring active_workspace.read() THEN workspace_config.read() (SAME order as snapshot_dispatch_context) - no lock-order inversion.
3. Returns None if EITHER value is absent, preserving the current skip-if-either-None semantics. A naive snapshot_dispatch_context() swap would default the config instead of skipping - that is a semantic change and is NOT acceptable.
4. background_db_hydration (~lifecycle.rs L336) and drain_pending_sync (~L397) migrated to the atomic reader; surrounding behavior preserved.
5. No .await on I/O while holding the read guards. #![forbid(unsafe_code)] intact; no new deps. Rollback = revert to the separate-await reads (no schema/format change).
