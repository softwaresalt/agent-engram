Extend engram's Rust-built canonical-path call resolution (091-F) to Python's module namespace so cross-module same-name calls resolve to the correct target instead of being dropped by name-only ambiguity. Layers on 094-F Python Calls extraction. Stash FE8B3B2D; **feature/spike fork "Option B" ratified** (product value operator-asserted; feasibility spike = GO). NOTE (F19 naming disambiguation): this feature-level "Option B" is the product/spike fork and is DISTINCT from the plan's implementation-level "Option A" (the bare-call-routing fork = provenance staging over the canonical post-pass); the two "Option" labels live in different decision namespaces and do not conflict.

<!-- BEGIN:description -->
Python modules ARE namespaces (foo/bar.py -> foo.bar). This feature adds a Python analogue of the Rust canonical machinery: (1) Python module-path + import-binding capture, (2) a Python function_meta.canonical_path populator, (3) a Python-aware canonical resolver branch that reuses the existing singleton/duplicate fail-closed core (function_ids_by_canonical_path) with ZERO CANONICAL-SCHEMA MIGRATION. Additive DB-layer changes are NOT zero but non-migrating: T5b adds a READ-ONLY public query helper in cozo_queries.rs (F9), and T7 reads/writes a version marker via the DB layer (a key in the existing schema_meta relation, R1) -- no function_meta/calls_edge migration and no file_node.content_hash contract change.

Resolution rule (frozen, PROVE-OR-FAIL-CLOSED; CALL-SITE-EFFECTIVE last-binding-wins per Python module scope): a bare call resolves to a canonical / module-qualified target ONLY when the call-site-effective binding of the callee name is STATICALLY PROVABLE (unambiguous across every modeled scope AND effective at the call site in execution order), else it fails closed. bare call -> the binding EFFECTIVE AT THE CALL SITE (the last provable binding preceding the call in execution order): a `from N import name` that rebinds over a local def BEFORE the call WINS -> N.name (import-rebind precedence, X2/X3); a local def that is the last binding before the call -> M.name; a function-body call whose module binding is contested by a later module-level rebind (invocation order unknown) -> fail closed (C7-1); module-level (top-level) call ordering is a v1 non-goal (top-level calls are not extracted); a name shadow-contested at any modeled scope (named import / star / non-import rebind / scoped import competing with a same-scope def) -> routed to staging / fail closed; else `mod.name()` with mod a bound module -> <mod>.name; else (star / relative / package-root / re-export / dynamic / unbound / local-shadow / unclear-order / shadow-contested) -> DROP (no canonical module-qualified edge; a UNIQUE cross-file bare call still keeps its LEGACY name-only edge per F3 — only the canonical layer drops, Z3).

Scope FROZEN: IN = module-level functions + module.func() disambiguation. OUT (documented non-goal) = instance-method dispatch (self.method()/obj.method()), which needs type inference. Related bug FF7DE872 (same-file same-name shadowing) is SPLIT OUT and INDEPENDENT — NOT subsumed here (the canonical index fails closed on the duplicate canonical_path rather than applying last-wins).

Independent of shipment 090-S / 095-F (operator-ratified: no blocking dependency). Sequences after 094-F (merged).
