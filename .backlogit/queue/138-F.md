Independently owned reliability follow-up carved out of 137-F after PR #364 merged. Copilot review on PR #364 found that shim::lifecycle::check_health collapses every fetch_health error - including a terminal IpcError::VersionMismatch or malformed/protocol-incompatible _health payload arriving after the initial readiness deadline - into a bare bool false. Both the request-triggered single-flight probe (src/shim/transport.rs forwarding_endpoint) and the bounded late-readiness monitor (src/shim/mod.rs spawn_late_readiness_monitor) therefore treat a permanently incompatible daemon as transient NotReady, emitting recoverable:true plus retry_after_ms forever instead of transitioning the session to a permanent fail-closed Degraded outcome. Scope: give the health probe a result-preserving return type so terminal health outcomes are separated from transient not-ready/unreachable outcomes, route only the latter through the recoverable cooldown path, and add concurrency coverage that proves the session-wide single-flight mutex and 250ms cooldown actually suppress a second in-flight probe. Explicitly out of scope for 137-F/130-S, which were verification-only with no production-logic edits.

## Goals

1. Terminal daemon health outcomes (protocol/version mismatch, `_health` error object, missing `result`, undecodable payload) transition the shim session to a permanent fail-closed `Degraded` state instead of an endless `recoverable: true` + `retry_after_ms` loop.
2. Transient outcomes (unreachable, timeout, reset, version-compatible non-ready status) keep the existing recoverable cooldown path with **no** behavior change.
3. Session-wide single-flight and the 250 ms cooldown are proven by behavior under genuine concurrency, not by code shape.
4. No probe amplification: the terminal latch strictly reduces probe volume; happy-path probe count is pinned exactly.

## Non-Goals

- Retuning `RECOVERY_PROBE_COOLDOWN` (250 ms) or the monitor backoff constants (50 ms -> 1 s).
- Changing the pre-deadline `ensure_daemon_running_inner` respawn ladder.
- Daemon-side `_health` payload evolution or a protocol version bump.
- Any edit under `docs/closure/**` (Ship-owned) or any re-release of `130-S` / `137-F`.
