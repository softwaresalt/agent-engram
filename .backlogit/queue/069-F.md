Reopen the tree-sitter TMDL grammar track after the 2026-07-04 safe-consumption
correction dispelled the `#![forbid(unsafe_code)]` blocker (Engram already
consumes ten C-based tree-sitter grammars — eleven languages — through the safe
`Parser::set_language(&tree_sitter_x::LANGUAGE.into())` API with zero `unsafe`).
This umbrella hosts the corrected evaluation gate (066.008-T, unblocked) and any
ROI-justified first-slice work: a vendored/generated TMDL grammar with an
external indentation scanner, a fixture-derived corpus, pinned grammar ABI, and
DAX/M captured as opaque blocks — integrated inside the Power BI ingestion
boundary (`crates/powerbi-tmdl-parser` → `src/services/powerbi_tmdl.rs`), never
as a generic code-graph `Language`. Predecessor safe-parser depth work landed in
068-F/068-S. Spike: docs/decisions/2026-07-04-tmdl-tree-sitter-safe-consumption-correction-spike.md.

<!-- BEGIN:goals -->
- Run the corrected tree-sitter feasibility gate (066.008-T) now that the safety
  mischaracterization is retired: decide vendor-vs-generate grammar sourcing,
  the indentation external-scanner strategy, and ABI pinning.
- If ROI-justified, land a first slice that beats the safe line parser on the
  real fixture corpus (block relationships, multiline measures, partitions,
  refs/annotations) while preserving `#![forbid(unsafe_code)]` in the crate.
- Keep the tree-sitter path inside the Power BI ingestion boundary; do not add
