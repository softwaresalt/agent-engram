Acceptance verification via the 081-F eval subsystem. New tests/integration/calls_recall_acceptance_test.rs indexes a fixture before/after the rec1 change, runs the 081.005-T graph resolution-recall + false_edge_rate metric, and gates on target-correctness against a hand-authored expected-edges manifest (ground-truth caller->callee id pairs) for the fixture.

METRIC CAVEAT: the 081-F false_edge_rate (count_dangling_calls_edges, src/db/cozo_queries.rs:2418) is a conservative LOWER BOUND — it detects dangling callees only, NOT calls resolved to an existing-but-wrong function, exactly the false edge rec1's unambiguous-name guard could introduce (follow-up D07F0919). So the aggregate metric CANNOT gate mis-resolution alone; the primary gate is the fixture ground-truth target-correctness assertion: every `calls_resolved_singleton` edge produced for the fixture MUST match the expected-edges manifest (correct callee id).

Width: verification/eval (1 test file + expected-edges manifest). Scenarios (4 — reduced from 5 per Copilot #239 by folding the standalone "edges counted" assertion into the manifest-match scenario): (1) post-change resolution_recall > pre-change; (2) aggregate false_edge_rate <= operator threshold (RetrievalEvalConfig.thresholds, 081.001-T) — supporting lower-bound signal only, not the sole gate; (3) every `calls_resolved_singleton` edge matches the expected-edges manifest AND the produced-edge count equals the manifest size (target-correctness + count folded into one scenario); (4) ambiguous names contribute no edge (skipped, not mis-resolved).

Closes the deliberation acceptance criterion. DEPENDS ON 082.008-T (post-pass), 082.009-T (lifecycle — acceptance runs against the stale-edge-safe implementation), 081.001-T (S1 contract/model), and 081.005-T (S3 graph metric).
