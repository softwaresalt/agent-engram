Wire `ExtractedEdge::References` edges into the code graph by resolving target names against indexed Class nodes. Currently the code graph service ignores References edges (no-op arms in `src/services/code_graph.rs` lines ~406 and ~886).

Implementation (from plan Unit 2):
- `src/services/code_graph.rs`: In both `index_workspace` and `sync_workspace` edge-processing loops:
  1. Add `queries.delete_edges_from_file("references", &file_id)` cleanup alongside existing `defines` cleanup.
  2. Replace `ExtractedEdge::References { .. } => {}` with resolution logic:
     - Call `queries.get_class_by_name(&target)` to look up the target.
     - If found: create `references` edge from file to class node via `create_references_edge`.
     - If not found: create `references` edge from file to itself with `qualified_name` set to the raw target string (preserves for later resolution). Per plan review P2-2, consider simply not persisting unresolved references as a simpler alternative.
  3. Increment `result.edges_created`.

Design: Resolution is workspace-scoped (cross-file). Per-reference DB lookup is O(N) — acceptable for correctness-first (plan review P2-4).

Qualified-name fallback (from deliberation Finding 2): When the target is schema-qualified (e.g., `"public.users"`), `get_class_by_name("public.users")` may return None if the class was registered as just `"users"`. The resolution logic MUST attempt a fallback: split on `.` and try the last segment. If the fallback also fails, treat as unresolved.

Tests: Integration test in `tests/integration/`:
1. Index SQL file with `CREATE TABLE users`, second with `SELECT * FROM users` → verify `references` edge to class node.
2. Index SQL with `SELECT * FROM nonexistent` → verify unresolved handling.
Execution posture: Test-first.
