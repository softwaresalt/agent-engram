## Step 5.5 Scope Guard

**In scope** = exactly the 064.004-T acceptance criteria:
1. `adapt_event` classifies `Created/Modified` markdown (`.md`, `.markdown`) as
   `ServiceAction::ReingestContent` (today it `Skip`s — this substrate must be
   produced before it can be gated).
2. The **live** `run_with_shutdown_v2` consumer gates each `ReingestContent` on
   `verify_markdown`: conformant → `ingest_single_file`; non-conformant →
   `warn!` + skip (not ingested).
3. Tests: valid md → ingested; invalid md (malformed frontmatter / empty body /
   unresolved `{{...}}`) → skipped + logged; unowned-path → skipped; adapt_event
   unit coverage; **no regression** to the code-file reindex/`sync_workspace` path.

**Out of scope (needs a new plan / new items):** refactoring or gating the legacy
v1 `run_with_shutdown` loop (comment only; confirm-or-remove is a separate item —
open question Q2); reactive handling of markdown `Deleted`/`Renamed` (still
`Skip`, swept by workspace sync); any CLI, schema, config, or startup/Ready-path
change; embeddings/backfill changes; the PR #188 hardening items (already shipped).

## Ship Notes (binding conditions from 072.001-R)

  `panic!`/`unwrap`/`expect` (workspace lint denies both); never break the receive
