Plan unit F43 - successful response provenance. Decorate successful read responses in `src/tools/mod.rs` with provenance taken from the CAPTURED request context - never from later global state. This is what makes a response self-describing about which generation produced it, even if a newer generation activated mid-request.

Execution posture: test-first.

<!-- BEGIN:acceptance-criteria -->
- Every successful read response carries provenance identifying the generation that produced it.
- Provenance is read from the captured context, never from current global state.
- A response produced during a concurrent activation reports the PINNED generation, not the newly activated one.
- Provenance shape is consistent across direct IPC, CLI and stdio MCP.
- `tests/contract/read_response_provenance_test.rs` asserts provenance correctness under concurrent activation.
<!-- END:acceptance-criteria -->
