Emptied/truncated files are skipped as `files_unchanged` by the TOCTOU race guard (code_graph.rs ~2020-2025/2054-2058), affecting ALL languages. When a .py is truncated to 0 bytes its prior symbols and canonical edges are left stale. Scope the fix to the shared guard, not 096-F Python code.

<!-- BEGIN:acceptance-criteria -->
- A file truncated to 0 bytes has its prior symbols/edges retracted on the next index/sync.
- Behavior is language-agnostic (verify at least one non-Python case).
- The original TOCTOU race the guard protects against is not reintroduced.
- RED test first: add a failing test that truncates a tracked .py to 0 bytes and asserts its prior symbols/edges are retracted after the next index/sync; confirm it fails against current `files_unchanged` behavior before implementing the fix.
<!-- END:acceptance-criteria -->
