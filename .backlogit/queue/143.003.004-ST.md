DURABLE, VERSIONED, CROSS-PROCESS RETRY LEDGER. Absorbs hardening constraint H13.

ORDERING, NON-NEGOTIABLE (Revision 3): the LEDGER PRECEDES ITS CONSUMER. The chain is 143.004.002-ST (failure taxonomy) then THIS LEAF (ledger) then 143.003.003-ST (backoff policy) then 143.003.005-ST (status surface). Revision 2 ordered the backoff policy BEFORE the ledger it consumes, which would have let the respawn bound be implemented against a counter that did not yet exist. A bound implemented against a non-existent counter is a bound that silently does not exist.

WHY THIS IS ITS OWN LEAF: the shim is invoked PER CLIENT CALL, so an in-process counter resets on every invocation. The bound would never fire in production while a single-process test still passed - a test that proves the wrong thing.

AC1 (CROSS-PROCESS DURABILITY): the counter survives shim PROCESS restarts. Asserted by a test that runs the shim as SEPARATE PROCESSES, not separate function calls in one process.
AC2 (INTER-PROCESS LOCK, FLUSH, ATOMIC REPLACE): every update is performed under an inter-process lock, written to a temp file, EXPLICITLY FLUSHED, and atomically replaced. write_all().await returning is NOT durability, and a later rename wins the race. A concurrent-writer test proves no lost update and no torn file. An equivalent proven atomic-replace protocol already used in this tree satisfies this requirement.
AC3 (VERSIONED FORMAT): the record format carries an explicit version field so a future shape change is detectable rather than silently misparsed. A test asserts an unknown future version fails closed rather than being misread as count zero.
AC4 (SCOPE KEY AND CONTAINMENT): the ledger is keyed on workspace plus branch plus endpoint, so one wedged workspace does not penalise others, and the file lives under the workspace .engram/ tree (constitution III/IV containment). A test asserts the resolved path is workspace-contained.

Attribution semantics (exact-child, reset, cooldown) and the CLI vs long-lived-MCP invocation shapes are owned by 143.003.007-ST. The backoff policy that CONSUMES this counter is owned by 143.003.003-ST.
