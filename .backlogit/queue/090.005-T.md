Deepen the CLI<->MCP parity drift guard (090.002-T) from existence+documentation parity to routing-identity + compiler-checked completeness. Copilot review of PR #259 raised two related gaps the current guard does not cover: (T5) every_documented_cli_command_resolves_to_help only proves the documented CLI command has a --help page; it does not verify the command actually invokes the mapped MCP method/handler, so a handler could be re-pointed (e.g. ngram health routed to get_workspace_statistics) while all parity tests stay green. Requires a structured CLI-command->MCP-method registry (does not exist today; CLI handlers in src/cli/commands/*.rs call services/IPC directly, not a 1:1 method table). (T6) dispatch_tool_names() text-parses the src/tools/mod.rs match by line; a NEW feature-gated dispatch-only arm wrapped across lines by rustfmt would be omitted, and since such a name is absent from all_tools(), neither the superset oracle nor every_dispatch_tool_is_documented would catch it. NOTE: the currently-known feature-gated tools (query_changes, index_git_history) ARE enforced via MCP_WITHOUT_CLI_ALLOWLIST + mcp_gap_allowlist_matches_documented_gap_rows, so present exposure is limited to a hypothetical future feature-gated tool. Deliverable: a compiler-checked dispatch-name registry in src/tools/mod.rs (single source of truth incl. feature-gated names) consumed by both the dispatch and the parity guard, plus a structured CLI-command->method mapping the guard can assert routing identity against. Grounding: src/tools/mod.rs (dispatch + should_record_metrics), tests/contract/lint_dax_cli_parity_test.rs, src/cli/commands/*.rs.
