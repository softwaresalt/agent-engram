U1 from the reviewed 5765BAAB plan. Build deterministic characterization using separate baseline and daemon workspaces with byte-identical corpus content. Prove the corpus yields a persisted `calls_resolved_singleton` edge through the known-GREEN in-process full-index path. Start one owned daemon on an initially empty second workspace, control watcher ingestion, pre-warm to settled state, seed the identical corpus, then issue exactly one explicit index and inspect through the same endpoint. Investigation/test width only; no production fix.

<!-- BEGIN:acceptance-criteria -->
- A separate baseline workspace/database proves exactly one expected cross-file singleton before daemon interpretation.
- Baseline and daemon corpus hashes match, but workspace/database identities differ.
- The owned daemon pre-warms on an empty workspace; watcher/background ingestion is suppressed or deterministically held; the graph is empty immediately before the measured explicit index.
- Explicit index and all graph queries use one daemon endpoint and correlated request IDs.
- Revision, binary version, corpus hash, daemon identity, timestamps, and before/after graph counts are recorded.
- Every probe is capped at five minutes with at most two equivalent reproductions; a current non-reproduction is recorded honestly.
<!-- END:acceptance-criteria -->
