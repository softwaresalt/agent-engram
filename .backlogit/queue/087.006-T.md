title: Persist PowerBI TMDL content records atomically to avoid partial-write hash skip
updated_at: 2026-07-16T18:34:34.0690457-07:00
---

In src/services/powerbi_indexer.rs (~line 1486), per-record upsert_content_record writes each ContentRecord carrying the file's final content_hash before all records for the file complete. If an early record persists but a later upsert fails, the next run builds existing_hashes from the partial record, treats the file as unchanged, and permanently skips the missing summaries. Fix: persist the file's records atomically, or write a completion marker only after every graph + content write succeeds and gate the hash-skip on that marker.
