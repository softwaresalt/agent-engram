Plan unit U1 (separate P-021 C4 work unit, opened forward after the F50 cycle): repair `scripts/verify-release-archive.py::verify_mcp_stdio` so the `--mcp` smoke reads the MCP JSON-RPC responses id 1 (`initialize`) and id 2 (`tools/list`) completely before it closes the shim's stdin. Then close stdin and still assert classified admission exit 10 and the stderr `panicked at` / `stack backtrace:` checks. Proven root cause: `Popen.communicate(payload)` closes stdin before `tools/list` is read. The shim then exits on EOF and stdout is cut at about 8192 chars on Windows (`ARCHIVE_SMOKE=FAIL: non-JSON stdout from MCP stdio`), and id 2 is missing on Linux CI. A read-first client gets the full 12,837-byte `tools/list` (21 tools) and exit 10. Source: docs/decisions/2026-09-25-archive-verifier-read-before-close-deliberation.md. Plan: docs/exec-plans/2026-09-25-archive-verifier-read-before-close-plan.md (plan-review PASS, attempt 3). Stash: 4EE241DC (survivor); BE626470 and F86074CD archived as merged duplicates. Execution posture: characterization-first, then test-first. SEQUENCING: final code task of 142-S (blocked by 142.054-T through 142.058-T; the edges sit on this task only). Executable only after explicit operator authorization adds it to active shipment 142-S (plan PA1).
