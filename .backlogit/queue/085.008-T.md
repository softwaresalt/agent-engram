<!-- BEGIN:description -->
Add model-scope INVALIDATION to complete P3's (085.003-T) model-scope aggregation. P3 aggregates the schema across sibling `.tmdl` files and emits `pbi_uses_field` reference edges during a full index pass, but the incremental indexer skips unchanged files by content hash (`src/services/powerbi_indexer.rs:911-927`). So when e.g. `Date.tmdl` adds/renames/deletes a column, an unchanged sibling `Sales.tmdl` measure is never re-resolved and its reference edges go stale. This task hooks the skip logic at MODEL-SCOPE granularity keyed by `canonical_tmdl_model_path` (`src/services/powerbi_tmdl.rs:85`): when ANY file in a model scope changes OR is deleted, reprocess / re-emit reference edges for ALL sibling `.tmdl` files in that scope, re-resolving each sibling's measure / calculated-column refs against the updated aggregated model-scope schema and superseding stale edges. Width: indexer (incremental-sync path). Reuses P3's aggregation + resolution helper + edge emission; adds only the invalidation trigger, sibling reprocessing, stale-edge cleanup, and an incremental-sync integration test. Provenance: PR #245 Copilot review cycle-4 (deferred — exceeded the 3-cycle review limit), routed by operator 2026-07-13 (Option A: fold into 085-F).
