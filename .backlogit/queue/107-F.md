HIGH-priority correctness follow-up from stash 42FB7CC5 / PR #301 / 099.004-T. Provable function-local Python imports are promoted to qualified `python_local` calls, but the full-index and incremental-sync staging producers attribute the caller with first-match `find_function_id`. Duplicate top-level caller names can therefore stage a trusted canonical target under an arbitrary duplicate and mint a wrong-origin edge. Reviewed direction: reuse typed `find_unique_function_id` at both producers, fail closed on ambiguous origin, preserve unique callers, and leave schemas/keys/target resolution unchanged. Source: docs/decisions/2026-07-31-python-qualified-staging-caller-attribution-decision.md. Hardened reviewed plan: docs/exec-plans/2026-07-31-python-qualified-staging-caller-attribution-plan.md (PASS).

- U1 RED target-identity harness covers duplicate callers on full index and incremental sync plus a unique-caller control.
- U2 makes both qualified staging producers use unique-only caller attribution; ambiguous callers do not stage and increment same_file_ambiguous_dropped.
- find_function_id and find_unique_function_id implementation semantics, staged-call schema/key, and Python target resolution remain unchanged; nearby documentation is accurate.
- Ordered Ship gates pass.
- Runtime closure records zero wrong-origin edges, no arbitrary staged row on sync, non-zero unique-caller control, and a release-exposure disposition. Ship only detects exposure and prepares a target-workspace-specific full-reindex handoff; no user/deployed workspace is mutated automatically. Verification occurs only after operator execution or explicit approval. If no affected binary shipped, closure records no migration/backfill.
- Rollback trigger: any wrong-origin edge, producer asymmetry, or unique-caller recall loss.

- Reuse existing typed ambiguity lookup and observability with no schema, key, CLI, or migration change.
