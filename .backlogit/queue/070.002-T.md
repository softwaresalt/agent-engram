## Summary

Fix S-PTM-25 (measure-DAX `:` truncation) in the safe TMDL parser. A measure
whose multiline DAX body contains a colon — e.g. `FORMAT ( NOW (), "HH:mm:ss" )`
— gets truncated because `looks_like_tmdl_property` treats any line containing a
colon as a TMDL property boundary, so the measure-body capture ends early and the
expression is dropped. Refine the heuristic to require a property-shaped `key:`
rather than the mere presence of a colon. Test-first: flip the pinned truncation
assertion to expect the captured body, then make the parser change green.

## Ground truth (already read)

- `crates/powerbi-tmdl-parser/src/lib.rs`
  - `looks_like_tmdl_property` :1128 — currently `trimmed.contains(':')` (the bare-colon shortcut, the root cause).
  - It is consumed by BOTH `should_finish_measure_capture` :627 (`... || looks_like_tmdl_property(trimmed) || ...`) and `capture_measure_body_line` :645 (same guard), so a colon-bearing DAX line both stops capture AND is refused as a body line → expression dropped.
  - Real TMDL property lines that must STILL be recognized: `dataType: decimal`, `lineageTag: ...`, `formatString: "HH:mm:ss"` (value contains a colon — still a property; leading key `formatString` is a bare identifier).
- Fixture `fixture_colon_in_dax()` :141 and finding `docs/decisions/2026-07-04-tmdl-eval-gate-finding.md` (S-PTM-25 row + fix localization).

## Implementation notes (for Ship, not done here)

- Refine `looks_like_tmdl_property` (:1128) so it returns true only when the text
  before the first `:` is a bare TMDL identifier (letters/digits/underscore,
  no spaces/parens/quotes) — i.e. a property-shaped `key:` at the line start —
  rather than "contains a colon anywhere".
  - `FORMAT ( NOW (), "HH:mm:ss" )` → text before first `:` is `FORMAT ( NOW (), "HH` (contains spaces/parens/quote) → NOT a property → body captured. ✓
  - `dataType: decimal`, `formatString: "HH:mm:ss"` → key is a bare identifier → still a property. ✓
- Centralizing the fix in `looks_like_tmdl_property` covers both call sites
  (`should_finish_measure_capture` + `capture_measure_body_line`) with one change.
  (Alternative: skip the bare-colon rule only while a measure-body capture is
  active — equivalent effect but threads capture state; the property-shape
  refinement is cleaner and preferred.)
- Verify no regression to `dataType:`/`lineageTag:`/relationship `fromColumn:`/`toColumn:` recognition via existing crate `#[cfg(test)]` tests + the differential harness.
