Plan unit F07 - generation-store containment and sealed targets. Implement `src/services/generations/store.rs` enforcing canonical containment under the configured generation root, regular-file checks, exclusive candidate directories, and the sealed `IndexTarget::{LegacyDirect, Candidate}` constructors.

Sealing is the mechanism that makes it impossible for the indexing service to accept an arbitrary path: only the store can mint an `IndexTarget`.

Execution posture: test-first.

<!-- BEGIN:acceptance-criteria -->
- Every resolved path is canonicalized and proven contained under the configured generation root.
- Symlink escape, `..` traversal, and absolute-path escape are all rejected.
- Non-regular files are rejected where a regular file is required.
- Candidate directories are exclusive; a second concurrent candidate for the same target is refused.
- `IndexTarget::LegacyDirect` and `IndexTarget::Candidate` can be constructed ONLY by the store.
- `tests/integration/generation_store_test.rs` covers containment, traversal rejection, and exclusivity.
<!-- END:acceptance-criteria -->
