## Description

The `run_script_busy_retry_mutable` helper in `src/db/cozo_queries.rs` (lines
300-327) retries SQLITE_BUSY errors silently. Add `tracing::warn!` logging to
each retry attempt for production observability.

## Approach

Inside the retry branch (after the `if` that checks for "locked" or "busy"),
add a warn-level tracing event before sleeping:

```rust
tracing::warn!(
    attempt = attempt + 1,
    max_attempts = MAX_ATTEMPTS,
    delay_ms = delay.as_millis(),
    error = %msg,
    "SQLITE_BUSY retry: retrying mutable run_script"
);
```

## Acceptance Criteria

- Each retry attempt emits `tracing::warn` with attempt count, max attempts,
  delay in ms, and error message
- `cargo clippy -- -D warnings -D clippy::pedantic` passes
- `cargo test` passes (retry behavior unchanged)
- No performance concern: retry path is exceptional, warn level is cheap
