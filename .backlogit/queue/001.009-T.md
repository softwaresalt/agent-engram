## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Write integration tests that prove the daemon safely handles multiple
simultaneous IPC connections from concurrent shim invocations.

Create `tests/integration/concurrent_sessions_test.rs` with test scenarios:
1. Three concurrent `list_tools` calls succeed without response corruption
2. Two concurrent `call_tool` (get_daemon_status) calls return consistent state
3. Concurrent `sync_workspace` + `call_tool` — indexing_in_progress serialization holds

Use tokio tasks to simulate concurrent shim connections. Use synchronization
barriers (channels/semaphores) rather than sleeps for deterministic behavior.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

<!-- SECTION:ACCEPTANCE_CRITERIA:BEGIN -->
- `tests/integration/concurrent_sessions_test.rs` exists and compiles
- All three test scenarios pass under `cargo test concurrent_sessions`
- Tests use tokio tasks with proper synchronization (no sleep-based timing)
- No unwrap/expect in test helpers — use proper error propagation
- Tests pass reliably in CI (no flakiness)
<!-- SECTION:ACCEPTANCE_CRITERIA:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Key code paths:
- `src/daemon/ipc_server.rs` — concurrent accept loop, `handle_connection`
- `src/server/state.rs` — `AppState` with `indexing_in_progress: AtomicBool`
- `src/shim/lifecycle.rs` — daemon spawn and health check

Out of scope: `active_connections` counter and `RateLimiter` (SSE-only, US5/T091, FR-025/T118).
