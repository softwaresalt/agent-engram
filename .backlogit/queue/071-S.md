## Description

<!-- BEGIN:description -->
Queued shipment for feature 071-F: stop wasting GitHub Actions minutes by skipping
the single CI `build` job (fmt/clippy/test/audit, ~3-3.5 min on ubuntu-latest) for
PRs and pushes that touch only doc/backlog/non-code paths, while preserving the
full clippy+test coverage verbatim for any PR that touches code. Grounded by the
required-check spike (`docs/decisions/2026-07-04-ci-build-skip-required-check-spike.md`):
`build` is **NOT** a required status check on `main` — the ruleset `PR-Required`
(id 12812291) enforces review + Copilot-review only (no `required_status_checks`
rule), and PR #200 (a backlog-only PR) ran a 3m14s build then merged with
`REVIEW_REQUIRED`/`--admin`. Because no status check is required, a workflow-level
`paths-ignore` on `ci.yml` (`push` + `pull_request`) for `.backlogit/**`,
`docs/**`, `**/*.md`, `.autoharness/**` is safe and sufficient — a single code
file re-arms the whole workflow, so code-PR coverage cannot be weakened. The
PR-title `if:` conditional was rejected (fragile/bypassable, no safer on required
checks). `release.yml` (tag-triggered) is out of scope. Reviewed and accepted via
071.001-R. Plan: `docs/exec-plans/2026-07-04-ci-build-skip-non-code-prs-plan.md`.
Awaiting Ship to claim.

## Step 5.5 Scope Guard

Single-width CI/workflow change. **In scope:** add a `paths-ignore` trigger filter
to BOTH `on.push` and `on.pull_request` in `.github/workflows/ci.yml` with
patterns `.backlogit/**`, `docs/**`, `**/*.md`, `.autoharness/**`; add a short
in-file comment recording the required-check coupling + spike pointer; verify
skip-vs-run behavior. **Out of scope (requires a new plan / new items):** any
broader CI redesign (matrix, job splits, cache strategy, moving fmt/clippy/test/
audit); `release.yml` changes (tag-triggered, unaffected); weakening or altering
code-PR coverage (the fmt→clippy→test→audit steps + feature flags stay identical);
any change to the `PR-Required` ruleset (e.g. adding a required status check);
PR-title-based conditionals (rejected). If `build` is ever promoted to a required
status check, adopting the companion always-passing job is a **new** work item —
do not expand 071.001-T.
