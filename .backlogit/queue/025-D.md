# Add capability-safe Unix parent directory fsync

## Problem Frame

<!-- BEGIN:problem-frame -->
The workspace-id publish protocol syncs file contents but returns without making the .engram directory entry durable after hard-link or rename publication and staging cleanup.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) accept the crash residual; B) reopen .engram by ambient path; C) safely reopen/duplicate the retained Dir, convert the duplicate with into_std_file(), and sync_all().
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Choose C as a separate width-isolated Unix release unit. Reopen/duplicate the retained Dir through cap-std 4.0.2, convert only the duplicate with into_std_file(), and sync_all() after staging cleanup. Attempt the barrier after publish returns Ok or AlreadyExists and before either new-file success or winner-read success can return. A parent-sync error overrides both success paths. Other publication failures retain their original error and are not masked by a sync attempt. Do not call sync_all() on the read-only Windows directory handle; preserve the Windows residual.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
Find a supported capability-safe Windows directory flush primitive without incompatible access rights. Before harvest, RED tests must cover new-file publish ordering, the AlreadyExists existing-winner path, and safe injected parent-sync failure on both otherwise-successful paths, with no unsafe or ambient reopen. Genuine multi-model adversarial review remains required because this changes workspace identity publication.
<!-- END:open-questions -->
