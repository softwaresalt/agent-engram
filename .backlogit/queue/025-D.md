# Add capability-safe parent directory fsync

## Problem Frame

<!-- BEGIN:problem-frame -->
The workspace-id publish protocol syncs file contents but returns without making the .engram directory entry durable after hard-link or rename publication and staging cleanup.
<!-- END:problem-frame -->

## Options

<!-- BEGIN:options -->
A) accept the crash residual; B) reopen .engram by ambient path; C) safely reopen/duplicate the retained Dir, convert the duplicate with into_std_file(), and sync_all().
<!-- END:options -->

## Chosen Direction

<!-- BEGIN:chosen-direction -->
Choose C as a separate width-isolated release unit. The public cap-std 4.0.2 APIs make this reachable without unsafe and without ambient path resolution.
<!-- END:chosen-direction -->

## Open Questions

<!-- BEGIN:open-questions -->
Verify Windows directory sync behavior and preserve publication errors. Multi-model adversarial review is required before harvest because this changes workspace identity publication.
<!-- END:open-questions -->
