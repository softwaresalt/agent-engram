<!-- BEGIN:description -->
Two tests in `tests/integration/release_archive_smoke_workflow_test.rs` fail on `main`. They were not caught because `.github/workflows/ci.yml` uses `paths-ignore`, and every recent PR was doc/backlog-only, so the `build` job was skipped. PR #371 (autoharness v1.5.0 merge-install) added non-markdown files under `scripts/`, which re-armed the full CI sequence and exposed them.

Both failures are pre-existing: the complete input closure of each test (`src/**`, `scripts/verify-release-archive.py`, `docs/closure/2026-08-29-v0.3.0-rc.1-verification.md`, `.github/workflows/*.yml`, `README.md`, `LICENSE`) is byte-identical to `main` in PR #371.

Failure 1 - archive_verifier_runs_the_unpacked_native_binary
`scripts/verify-release-archive.py` emits `ARCHIVE_SMOKE=FAIL: non-JSON stdout from MCP stdio` while validating the packaged MCP stdio path. The `tools/list` response is well-formed JSON-RPC, so the verifier stdout parser is rejecting valid output (likely a line-length, chunking, or single-line-read assumption).

Failure 2 - verification_record_separates_g1_evidence_from_g3_artifact_proof
`docs/closure/2026-08-29-v0.3.0-rc.1-verification.md` contains `## G1 pre-merge verification` but not the required `## G3 post-publish verification` boundary marker asserted at `release_archive_smoke_workflow_test.rs:731`. The G3 section was never written after the v0.3.0-rc.1 assets were published.
