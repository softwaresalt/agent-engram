<!-- BEGIN:description -->
`.github/workflows/ci.yml` uses `paths-ignore`, and `build` is not a required status check on `main`. Every recent PR was doc/backlog-only, so the `build` job was skipped across several merges. PR #371 added non-markdown files under `scripts/`, re-armed the full CI sequence, and exposed two latent failures in `tests/integration/release_archive_smoke_workflow_test.rs`.

Resolved in PR #371
`verification_record_separates_g1_evidence_from_g3_artifact_proof` failed because commit `2ee9ceac` ("chore: archive shipment 132-S closure", merged via PR #370) renamed the contract-required boundary marker `## G3 post-publish verification` to `## Final post-publish and native verification` in `docs/closure/2026-08-29-v0.3.0-rc.1-verification.md`. All evidence content survived the rename; only the marker was lost. PR #370 was doc-only, so `paths-ignore` skipped `build` and the regression merged undetected. PR #371 restores the canonical heading.

Still open
`archive_verifier_runs_the_unpacked_native_binary` fails on Windows hosts. `scripts/verify-release-archive.py` reports `ARCHIVE_SMOKE=FAIL: non-JSON stdout from MCP stdio` while validating the packaged MCP stdio path, even though the `tools/list` response is well-formed JSON-RPC. The verifier stdout parser appears to assume a bounded line length or a single-line read; the `tools/list` payload for the full engram catalogue is large enough to break that assumption. The test passes on the `ubuntu-latest` CI runner, so this is Windows-specific and does not currently block CI.

Underlying blind spot
This is the exact scenario called out in the `ci.yml` header comment and `docs/decisions/2026-07-04-ci-build-skip-required-check-spike.md`: `paths-ignore` combined with a non-required `build` check lets code-affecting regressions land through doc-only PRs and stay invisible until an unrelated PR happens to re-arm CI.
