## Daemon Startup Freshness Detection — Skip Re-Index When DB Is Current

### Problem

When the user runs `engram sync --direct` (045-F) to pre-populate the code graph, then launches Copilot (which spawns the daemon via `.mcp.json`), the daemon's `background_db_hydration()` pipeline runs `detect_offline_changes()` to find files that changed while it was offline. If the `--direct` indexer already brought the DB up to date, this scan should return 0 changes and the daemon should skip re-indexing entirely.

### Current State

The pipeline already has the right structure:
1. `detect_offline_changes()` compares on-disk file hashes against `file_hash` table
2. If `offline_count == 0`, `sync_code_graph()` is skipped (line 325 in lifecycle.rs)
3. `index_workspace()` already calls `record_file_hash()` after each file (line 448 in code_graph.rs)

**Gap 1**: `sync_workspace()` does NOT call `record_file_hash()` — so an incremental sync via `--direct` leaves stale hashes and the daemon will detect phantom changes on next startup.

**Gap 2**: `hydrate_code_graph()` always runs on startup regardless of freshness — it re-loads JSONL files even when the DB already has current data. This adds unnecessary startup latency.

**Gap 3**: No index-level freshness marker — the daemon has no fast way to know "this DB was last indexed at time T against workspace state X" without scanning all files.

### Fix

1. **Add `record_file_hash` to `sync_workspace()`** — after each successfully synced file, record its hash (matches what `index_workspace` already does). This is a bug fix.

2. **Write an index freshness marker** — after `index_workspace()` or `sync_workspace()` completes, write a `last_indexed_at` timestamp + workspace content hash to a `index_freshness` relation in CozoDB. The daemon can check this on startup to fast-path the offline detection.

3. **Fast-path `hydrate_code_graph()`** — if the DB already contains code graph data (check `code_files` relation count), skip JSONL re-loading. The JSONL files are a dehydration artifact for persistence; if the DB is already populated, they're redundant.

### Acceptance Criteria

- After `engram sync --direct`, daemon startup detects 0 offline changes and skips re-index
- After `engram index --direct`, daemon startup detects 0 offline changes and skips re-index
- `sync_workspace()` records file hashes for all synced files
- Daemon startup logs `"index is current, skipping re-index"` when freshness check passes
- `cargo test` passes
- `cargo clippy -- -D warnings -D clippy::pedantic` clean

### Scope

- `src/services/code_graph.rs` — add `record_file_hash` calls to `sync_workspace()`
- `src/services/code_graph.rs` — write freshness marker after index/sync completion
- `src/tools/lifecycle.rs` — fast-path `background_db_hydration` when DB is current
- `src/db/cozo_queries.rs` — add `index_freshness` relation + queries
- `src/services/hydration.rs` — skip JSONL reload when DB is already populated
