Correct two durable workflow defects at opposite ends of the checkpoint lifecycle in the installed .github/ agent harness.

DEFECT 1 (stash A1D95672, operator-reported, authoritative): In dark factory mode (P-017) the Orchestrator demands the operator re-type a checkpoint filename to continue the SAME bounded run. Observed on the 139-S dark run. Root cause is a category error: Step 0.0b's unconditional operator-selection/confirmation gates were written for a COLD START discovering an unknown, possibly-live FOREIGN session; they are wrong when applied to a WARM continuation of the current bounded run whose checkpoint is the run's own pause marker inside a pre-authorized scope.

DEFECT 2 (stash 4EF24729, P-021 deferred expansion): Resolving a tracked Ship checkpoint after its closure PR merged strands the resolution commit on the merged branch, so main keeps reporting status:active and a closure-of-closure PR becomes necessary. Observed on 139-S (commit 43e70430 never reached main; repaired by PR #395).

SOLUTION: An eight-condition conjunctive AND gate (DARK_CONTINUATION_PREDICATE) authorized by an amendment to P-017, implemented in Orchestrator Step 0.0b and mirrored in the Stage and Ship owner-side crash-resumption protocols. Any false condition falls through to the EXISTING, UNCHANGED fail-closed operator path, so a mis-evaluation can only ever produce MORE operator interaction, never less. Plus a resolution-ordering fix that places checkpoint resolution before the closure PR's final reviewed HEAD, with merge-path and startup-path orphan-detection assertions.

Preserves P-001/P-009/P-014/P-016/P-017/P-020. Conveys continuation authority ONLY -- never merge, admin-fallback, or destructive approval.
