Correct two durable workflow defects at opposite ends of the checkpoint lifecycle in the installed .github/ agent harness.

DEFECT 1 (stash A1D95672, operator-reported, authoritative): In dark factory mode (P-017) the Orchestrator demands the operator re-type a checkpoint filename to continue the SAME bounded run. Observed on the 139-S dark run. Root cause is a category error: Step 0.0b's unconditional operator-selection/confirmation gates were written for a COLD START discovering an unknown, possibly-live FOREIGN session; they are wrong when applied to a WARM continuation of the current bounded run whose checkpoint is the run's own pause marker inside a pre-authorized scope.

DEFECT 2 (stash 4EF24729, P-021 deferred expansion): Resolving a tracked Ship checkpoint after its closure PR merged strands the resolution commit on the merged branch, so main keeps reporting status:active and a closure-of-closure PR becomes necessary. Observed on 139-S (commit 43e70430 never reached main; repaired by PR #395).

SOLUTION: An eight-condition conjunctive AND gate (DARK_CONTINUATION_PREDICATE) authorized by an amendment to P-017, implemented in Orchestrator Step 0.0b and mirrored in the Stage and Ship owner-side crash-resumption protocols. Plus a resolution-ordering fix that places BOTH the session and compensating checkpoint resolutions before the closure PR's final reviewed HEAD - so both ride the same merge and neither is orphaned - with merge-path and startup-path orphan-detection assertions and a LAST_MILE_RECOVERY protocol for the resulting checkpoint-free window before merge.

SAFETY MODEL (corrected in revision 4 - H27): mis-evaluation is DIRECTIONAL and the two directions are NOT symmetric. A FALSE NEGATIVE (a genuinely-true condition evaluates false) degrades safely: it falls through to the EXISTING, UNCHANGED fail-closed operator path and costs only MORE operator interaction. A FALSE POSITIVE (a genuinely-false condition evaluates true) is the PRINCIPAL SAFETY RISK: because each condition is NECESSARY, a single wrongly-true conjunct satisfies the entire gate, REMOVES operator interaction, and can auto-route an ineligible or WRONG checkpoint. Conjunctivity bounds ineligibility, not evaluation error. Implementation MUST therefore ensure that any condition which cannot be PROVEN true evaluates false (missing, malformed, ambiguous, stale, or failed lookups all decline), that incomplete candidate enumeration is an ERROR rather than evidence of sole candidacy, and that every mutable conjunct is re-evaluated immediately before routing AND AGAIN BY THE OWNER IMMEDIATELY BEFORE RESTORE to bound the TOCTOU window. Verification must exercise the false-positive direction explicitly (plan scenarios S28-S35, S45, plus one-condition-false/seven-true cases for all eight conjuncts). Do NOT restate the withdrawn claim that "a mis-evaluation can only ever produce more operator interaction, never less" - that holds for false negatives only.
