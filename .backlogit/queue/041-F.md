## Description

CozoDB 0.7.6 panics via `unwrap()` at `sqlite.rs:49` when encountering
SQLITE_BUSY. The workspace has accumulated multiple mitigation layers
(fd-lock, per-script retry, metrics, platform-specific test ignores). All
mitigations can be removed once CozoDB ships a release that handles
SQLITE_BUSY gracefully by returning an error instead of panicking.

This feature consolidates 3 stash entries (1092D3D6, 100EACD8, D13A3452)
into a single blocked feature awaiting upstream CozoDB >= 0.8 release.

## Watch Trigger

Monitor crates.io for `cozo >= 0.8` with confirmed SQLITE_BUSY error
propagation (not panic). When available:

1. Move this feature blocked → queued
2. Notify Stage agent for shipment assembly

## Scope

- Upgrade CozoDB dependency to >= 0.8
- Remove fd-lock workaround in `connect_db`
- Remove `run_script_busy_retry_mutable` retry loop and atomics
- Remove `get_mutable_script_retry_metrics` MCP tool (decrement TOOL_COUNT)
- Remove `cfg_attr` platform-specific test ignore annotations
- Fix rehydration test design (verify rehydrated-only state before auto-index)

## Blocker

**Blocked on**: CozoDB >= 0.8 release on crates.io that gracefully handles
SQLITE_BUSY by returning an error rather than panicking.
