Close the two post-ship lineage freshness gaps in src/services/notebook_indexer.rs (PR #281 findings 4 + 5), split out of U4 for width/granularity isolation. (1) BACKFILL for UNCHANGED notebooks: index_notebook_source skips already-indexed notebooks by content-hash BEFORE extraction (notebook_indexer.rs:153-156) with no force/version input, so after this feature ships, notebooks indexed by a prior version NEVER receive lineage on a normal re-index. Add a lineage/notebook-extractor SEMANTIC-VERSION fingerprint to the skip predicate (re-extract when the persisted fingerprint is older than the current extractor version) OR an explicit backfill path; add an upgrade test proving an UNCHANGED, previously-indexed notebook gains lineage after a version bump. (2) WHOLE-NOTEBOOK DELETION: sweep_deleted_notebook_files (notebook_indexer.rs:238-263) deletes content records but performs NO lineage cleanup, leaving evidence + edges permanently stale. Extend the sweep to call delete_lineage_by_scope(notebook_path) (the U1 3-step cascade) for each deleted notebook; add a whole-file-deletion test asserting the notebook's evidence is gone, edges are GC'd when unevidenced, and datasets still evidenced elsewhere survive. Domain: notebook-path (integration; width-isolated from parsers/schema). Blocked by U4. Plan Unit 4b.
