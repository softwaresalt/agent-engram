Close the two post-ship lineage freshness gaps in src/services/notebook_indexer.rs (PR #281 findings 4 + 5), split out of U4 for width/granularity isolation. (1) BACKFILL for UNCHANGED notebooks: index_notebook_source skips already-indexed notebooks by content-hash BEFORE extraction (notebook_indexer.rs:153-156) with no force/version input, so after this feature ships, notebooks indexed by a prior version NEVER receive lineage on a normal re-index. DURABLE FIX (cycle-5 F5): content_record carries only content_hash (src/models/content.rs:26) with NO version slot, so the lineage-extractor SEMANTIC-VERSION fingerprint is persisted DURABLY in the U1a lineage_index_state relation (via upsert_lineage_index_state / lineage_index_version) — NOT a constant + in-memory check. NOTE (AR-03): the U4 write-path already stamps upsert_lineage_index_state UNCONDITIONALLY for every EXTRACTED notebook (incl. ZERO-lineage), so this version+hash skip is durable for zero-lineage notebooks too — a zero-lineage notebook is NOT re-extracted every run (the earlier edge-driven-only stamping claim was false for that case). Extend the skip predicate to ALSO require the persisted extractor version to match the current one; a version BUMP forces re-extraction (backfill) of unchanged notebooks, then re-persists the new version so the notebook is SKIPPED AGAIN at the new version — proving the check is neither a one-shot nor a perpetual reindex. No forced full-reindex flag required. Tests: an UNCHANGED notebook with a bumped extractor version re-extracts and its lineage appears (upgrade/backfill), then a SUBSEQUENT re-index at the same version is SKIPPED (durable, not perpetual reindex), and the persisted version SURVIVES a store re-open (cycle-5 F5); a ZERO-lineage notebook (produced no edges) is stamped by U4 and hash+version SKIPPED on the 2nd same-version run — NOT perpetually re-extracted (AR-03); AND a notebook whose lineage graph rows EXIST but whose lineage_index_state row is ABSENT — simulating a PRE-STAMP partial-write failure, WITHOUT fault injection — is NOT skipped by the version+hash predicate and RE-EXTRACTS (the recovery invariant, which holds because the U4 write-path issues its stamp as the FINAL write — I1). (2) WHOLE-NOTEBOOK DELETION: sweep_deleted_notebook_files (notebook_indexer.rs:238-263) deletes content records but performs NO lineage cleanup, leaving evidence + edges permanently stale. Extend the sweep to call delete_lineage_by_scope(notebook_path) (the U1a' 4-step cascade — which now ALSO deletes the notebook's lineage_index_state row, AR-22) for each deleted notebook; add a whole-file-deletion test asserting the notebook's evidence is gone, edges are GC'd when unevidenced, its lineage_index_state row is deleted (AR-22), and datasets still evidenced elsewhere survive. Granularity: 2 functions, 3 test scenarios (backfill/version-skip; recovery-when-stamp-absent; whole-notebook deletion) — within the 2-hour gate. Domain: notebook-path (integration; width-isolated — the version-state RELATION is U1a's schema, U4b only reads/writes it via the U1a"/U1a' helpers). Blocked by U4 write-path (095.015-T).
