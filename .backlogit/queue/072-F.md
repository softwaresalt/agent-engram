Bug fix follow-up to 073-S / PR #207. A post-merge Copilot review on PR #207 found that DaemonError::NotReady's #[error(...)] message was augmented with a '--direct' escape-hatch hint, but NotReady is a SHARED variant. Its second call site (wait_for_daemon_exit in src/shim/lifecycle.rs:392-395, reached via respawn_daemon) returns NotReady when the OLD daemon fails to SHUT DOWN during respawn. In that shutdown-wait path the '--direct' hint is misleading and cannot succeed: the stuck daemon still holds the daemon lock, so 'engram index --direct' fails at src/cli/direct.rs:75-79 ('daemon is already running (pid ...); stop it before using --direct mode'). Fix: split the message so the shutdown-wait path does not surface --direct. Severity: LOW (misleading hint in a rare respawn path) but real. Source: PR #207 review finding + closure report docs/closure/2026-07-04-notready-direct-hint-adversarial-review.md.
