Plan unit F18 - startup activation gate. Implement `src/daemon/startup_activation.rs` against the seam F04a declared: bind the socket first, report `starting`, call `activate_initial`, and withhold both readiness and read dispatch until exactly one generation context is open.

F18 is the SOLE WRITER of `ReadinessView`. It never gates an individual request - `request_entry::admit` (F20) is the only admission authority and merely consults the readiness state F18 publishes.

Managed mode is unchanged.

Execution posture: test-first.

<!-- BEGIN:acceptance-criteria -->
- The daemon binds its socket before attempting activation, so clients get a connection rather than a connection error during startup.
- Status is reported as `starting` until activation completes.
- `activate_initial` must succeed before readiness is published.
- Read dispatch is withheld until one context is open.
- A failed initial activation reports a typed F38 availability error and does NOT report ready.
- F18 writes `ReadinessView` and nothing else reads/writes it as a writer.
- F18 contains no request-admission logic.
- Managed-mode startup behavior is unchanged.
- `tests/integration/read_server_startup_activation_test.rs` covers success, failure, and the managed-mode regression.
<!-- END:acceptance-criteria -->
