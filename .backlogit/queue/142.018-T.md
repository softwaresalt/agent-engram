Plan unit F17 - generation activation service. Implement `src/services/generations/activation.rs` with `activate_initial` and single-flight `maybe_activate_newer`.

Activation enforces: typed manifest parsing, bounds checks, branch and workspace identity match, store resolution, digest revalidation, the F09 open, an activation deadline, an immutable rejection cache so a known-bad revision is never retried, and transient backoff for recoverable failures. Activation is triggered ONLY by startup reconciliation and request-entry reconciliation - there is no control endpoint and no notification path.

Execution posture: test-first. RS5 - this unit is ActionRisk high and requires operator approval before Ship implements it.

<!-- BEGIN:acceptance-criteria -->
- `activate_initial` opens and validates a generation, or fails with a typed F38 error.
- `maybe_activate_newer` is single-flight: concurrent callers coalesce into one activation attempt.
- Only a revision strictly greater than the currently opened revision is activated.
- Manifest parsing is typed; bounds are enforced.
- Branch identity and workspace identity are verified before activation.
- Digests are revalidated before the generation is opened.
- An activation deadline bounds the attempt.
- A permanently rejected revision enters an immutable rejection cache and is never retried.
- Transient failures back off rather than spin.
- Failed activation leaves the currently active generation untouched and still serving.
- No generation-control endpoint is introduced.
- `tests/integration/generation_activation_test.rs` covers initial, newer, concurrent, rejected and transient paths.
<!-- END:acceptance-criteria -->
