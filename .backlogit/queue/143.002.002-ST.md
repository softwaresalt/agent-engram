Connection classification and lease release on EVERY termination path. Split out of 143.002-T in Revision 3.

AC1 (CLASSIFICATION POINT, LOAD-BEARING): classification occurs only AFTER enough request information exists to decide - i.e. after the request frame/method is read - and NEVER at bare accept(). At accept() the daemon cannot distinguish a health probe from a real client, so classifying there would guess, and guessing probe would starve a genuine client into premature shutdown.
AC2 (CLASSIFICATION TEST): a bare connect-and-drop is classified ProbeOnly and acquires no lease; a connect-then-request is classified UsefulWork and holds a lease for the request lifetime.
AC3 (NO PREMATURE SHUTDOWN): a genuine tool call whose execution EXCEEDS the idle timeout is not cut off.
AC4 (CANCELLED REQUEST): a request cancelled mid-flight releases its lease EXACTLY ONCE - no leak (the daemon still reaches idle expiry afterwards) and no double release (the daemon is not cut off while other work is in flight).
AC5 (ERRORED REQUEST AND EARLY RETURN): a request returning Err, and a request taking an early ? return, each release exactly once, asserted separately from AC4.
AC6 (CLIENT DISCONNECT MID-REQUEST): a client that disconnects mid-request releases exactly once.
AC7 (138-S BOUNDARY, NON-NEGOTIABLE): this leaf performs NO read and NO write of ReadinessView or any 138-S-owned activation state. Readiness is NOT an input to classification - classification is purely a property of the connection. Proven by (i) an explicit enumeration of the touched call sites recorded in the change and (ii) a test asserting classification results are identical against a ready and a not-ready daemon.
