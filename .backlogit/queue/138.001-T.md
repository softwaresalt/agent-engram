Origin: Copilot review finding on PR #364 (was 137.006-T under 137-F; re-parented, not cloned). Replace the bool-flattening health probe with a result-preserving outcome type so terminal incompatibility is separable from transient not-ready. Add HealthOutcome { Ready, Transient { reason }, Terminal { reason } } and pub async fn probe_health(endpoint) -> HealthOutcome in src/shim/lifecycle.rs; refactor fetch_health to return a HealthProbeError that carries the terminal/transient discriminant AT CONSTRUCTION. This is mandatory because fetch_health today builds IpcError::ReceiveFailed for the daemon-error, missing-result, and undecodable-payload cases - the same variant ipc_client::send_request yields for genuine transport failures - so downstream re-classification by matching on EngramError is provably impossible. Retain check_health as a thin bool adapter (matches!(probe_health(..), Ready)) so no non-recovery caller changes. Do NOT change the public EngramError/IpcError surface and do NOT touch the pre-deadline ensure_daemon_running_inner respawn ladder. Width: src/shim/lifecycle.rs only.

<!-- BEGIN:acceptance-criteria -->
- `HealthOutcome` is a public, exhaustively-matched enum with exactly `Ready` / `Transient { reason }` / `Terminal { reason }`.
- Classification rule (conservative, fail-closed only on proof): `Terminal` requires a received, parsed-enough response proving incompatibility - protocol/version mismatch, `_health` JSON-RPC error object, missing `result`, undecodable payload. Silence, refusal, timeout, and reset are ALWAYS `Transient`. A version-compatible non-ready `status` is `Transient`.
- `check_health` retains its `-> bool` signature and behavior for all existing callers; no non-recovery call site is edited.
- Public `EngramError` / `IpcError` variants are unchanged.
- `ensure_daemon_running_inner` and the pre-deadline respawn ladder are unchanged.
- Terminal outcomes log at `tracing::warn!` with `endpoint`/`expected`/`actual`; transient stays at `debug!`.
- No `unsafe`; no `unwrap`/`expect` in the new production path.
- Scenarios T1-T4 and R1-R2 from the plan compile and now fail only on the not-yet-wired consumers (138.004-T / 138.005-T), not on classification.
- R3 (`shim_recovers_after_timed_out_daemon_later_becomes_ready`) stays green, unmodified - the over-terminalization guard.
- G6 acceptance note (accepted residual risk): a truncated `_health` write surfaces as a framed-transport receive failure (transient), not a decode failure. Do NOT add speculative defensive logic for it.
- Width isolation: no edits outside `src/shim/lifecycle.rs`.
