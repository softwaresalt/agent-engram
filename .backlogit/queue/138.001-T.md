PHASE 3 (behavior). Width: src/shim/lifecycle.rs ONLY. Origin: Copilot review finding on PR #364 (was 137.006-T under 137-F; re-parented, not cloned). Replace the bool-flattening health probe with a result-preserving outcome type. Add HealthOutcome { Ready, Transient, Terminal(TerminalKind) } and pub async fn probe_health(endpoint) -> HealthOutcome; refactor fetch_health so the discriminant is carried AT CONSTRUCTION. Mandatory because fetch_health today builds IpcError::ReceiveFailed for the daemon-error (lifecycle.rs:99-106), missing-result (:108-112) and undecodable-payload (:113-117) cases - the SAME variant ipc_client::send_request yields for genuine transport failures - so downstream re-classification by matching on EngramError is provably impossible. TerminalKind is a CLOSED enum: VersionMismatch{expected,actual}, MethodNotFound, MissingResult, UndecodablePayload. It carries NO free-form reason String - revision 1's Terminal{reason} would have propagated the daemon's arbitrary JSON-RPC error.message (embedded verbatim at lifecycle.rs:99-105) into the permanent client payload, leaking paths/env values. Daemon-supplied text is debug!-only and NEVER reaches the wire, the warn fields, or the durable record. CLASSIFICATION RULE (conservative; terminal only on proof): ANY Err returned by ipc_client::send_request is TRANSIENT BY CONSTRUCTION - this is the load-bearing invariant and it covers refusal, timeout, reset, EOF, truncation and non-JSON, because send_request decodes the JSON itself at src/shim/ipc_client.rs:104. Only errors fetch_health constructs AFTER send_request returned Ok are terminal candidates. JSON-RPC error -32601 -> Terminal(MethodNotFound); ANY other code including -32603/-32700/-32600/unknown -> TRANSIENT. Missing result -> Terminal(MissingResult). Undecodable result -> Terminal(UndecodablePayload). ensure_protocol_compatible rejection -> Terminal(VersionMismatch). Version-compatible status!='ready' -> Transient. OBSERVABILITY: all terminal outcomes log tracing::warn! with endpoint and terminal_kind; expected/actual are emitted ONLY for VersionMismatch - the other three kinds become terminal before any protocol version exists, so requiring those fields universally (revision 1) was impossible. Retain check_health as a thin bool adapter (matches!(probe_health(..), Ready)) so no non-recovery caller changes. Do NOT change the public EngramError/IpcError surface and do NOT touch the pre-deadline ensure_daemon_running_inner respawn ladder.
