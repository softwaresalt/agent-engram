Source stash 75DAF33D (medium bug, PR #301 follow-up). A non-forced ordinary index authoritatively reads an indexed file as zero bytes, continues through parse teardown, deletes function metadata, but retracts old direct edges only when `force=true`. If another file hash-skips, the later dangling-edge sweep is not certified, so the empty path can retain a code-file record and orphan raw direct rows. Add sync-parity empty-read eviction: immediately after successful content read and before hash/parse, use the existing `handle_deleted_file` primitive for an indexed zero-byte path; never act on metadata or read failure. Preserve the documented `files_reconciled` meaning; count the path as skipped and add no response fields.

<!-- BEGIN:acceptance-criteria -->
- RED first: ordinary-index an edge-bearing file plus an unrelated control file; rewrite only the edge-bearing file to zero bytes and leave the control byte-identical.
- The second non-forced ordinary index hash-skips the control (`any_hash_skipped=true`) yet removes the empty path's code-file record, functions/classes/interfaces, staged calls, and all direct/resolved/raw dangling call rows through `handle_deleted_file`.
- The unchanged control file, symbols, and live edges remain present; the code-graph generation marker does not advance on the hash-skipped run.
- A never-indexed empty file is a skip/no-op. Metadata zero, read failure, parse failure, and non-empty changed files are not treated as this deletion case.
- `IndexResult.files_reconciled` semantics and all public/CLI/MCP/schema contracts remain unchanged; no new deletion primitive.
<!-- END:acceptance-criteria -->

<!-- BEGIN:implementation-notes -->
Single full-index teardown width; target <=100 minutes and <=2 files. Place the zero-byte branch after successful `read_to_string` and before content hash/upsert/parse. Look up the existing code-file record, call `handle_deleted_file` with its stored ID, increment `files_skipped`, and break the per-file block. Serialize after R1 because both edit `index_workspace_impl`. Dark-mode stop: return blocked if cleanup affects a non-empty/read-failed path, loses the unchanged control, reveals generalized non-empty stale-edge teardown, or exceeds four scenarios/two files.
