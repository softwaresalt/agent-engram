Route (a-1). Execution posture: test-first. The harness-architect re-qualifies this task's F50 share on the slot's base tree; parked commits `c269fa79` and `41dd5081` are reference only.

The F50 machine runs Build -> Seal -> Publish -> DaemonVerified -> HealthVerified -> CliProbeVerified -> McpProbeVerified -> Succeeded, or a typed `Failed`, with ONE deadline and ONE expected generation. This supersedes the 118-S Guardrail 4 fail-open behavior: an agent session must not be able to begin with Engram degraded.

Scope (this task's share of F50), in `crates/engram-indexer/src/preflight.rs`:
- The DaemonVerified, HealthVerified, CliProbeVerified and McpProbeVerified stages of `ProductionVerifier`: confirm the daemon picked up the expected generation through request-entry reconciliation, then verify health and representative CLI and MCP reads before the machine may report `Succeeded`. Verification is observational only (R48): the supervisor waits for the daemon to reconcile the durable manifest at request entry and never pushes, notifies, or commands activation (amended R39/R45).
- Stage-to-facade composition (this task's rows): DaemonVerified = `wait_for_generation(PREFLIGHT_READ, expected)`; HealthVerified = `probe_cli_read(HEALTH_READ).accepted`; CliProbeVerified = `probe_cli_read(PREFLIGHT_READ)` with `generation_id == expected`; McpProbeVerified = `probe_mcp_read(PREFLIGHT_READ)` with `generation_id == expected` AND `data_fingerprint ==` the CLI fingerprint.
- The PA-2b real-chain cases (their RED belongs to this task): drive `ProductionVerifier` with `env!("CARGO_BIN_EXE_engram")`; a spaced read-server git fixture reaches `Succeeded`, and a managed-mode fixture fails at `DaemonVerified`.
- The verifier's six pedantic lint fixes: a typed `VerifyError` replaces `Result<(), ()>`, plus the `# Errors` and `#[must_use]` attributes.
- This task writes its own RED cases at its own Step 2 in `tests/integration/preflight_gate_test.rs` (target `integration_preflight_gate`).

Not in this task: the typed machine and its mock-driven cases (Slot-09a, `142.078-T`); the Build, Seal and Publish stages (Slot-09b, `142.079-T`).
