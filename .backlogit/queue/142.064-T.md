Scope:
- Single-source identity (REPLACE, not duplicate): `run_read_server_startup` drops `validate_workspace_path`, the inline `canonicalize_workspace` / `resolve_git_branch` / `workspace_hash` derivation and their imports, and starts with `let layout = read_server_layout(&workspace)?;`; the same `layout` value feeds the snapshot and the activator.
- Install before readiness: when `generations_root` is a directory at startup, the new private `install_generation_gate(&state, &layout)` runs AFTER workspace publication and BEFORE `set_hydration_ready_for_generation` (open store, build `GenerationActivator` + `ReadServerStartupGate`, `socket_bound()`, install via `set_generation_activator` and the new `set_read_server_gate`); no manifest read, hash, or copy; `_health` unchanged.
- Background driver: private `drive_generation_activation(state, layout, shutdown)` spawned after readiness; bounded backoff 100 ms doubling to a 2 s cap; late install only for a root absent at startup; activation on a new non-zero revision; same-revision Transient retry within the activation deadline; Permanent never retried (5C873386); publication-last; ends on shutdown.

Owned files (production): `src/daemon/lifecycle_policy.rs` (`run_read_server_startup` + new private `install_generation_gate` + new private `drive_generation_activation`); `src/server/state.rs` (one `RwLock<Option<Arc<ReadServerStartupGate>>>` slot + `set_read_server_gate` / `read_server_gate`).
Harness (RED first): `tests/integration/read_server_generation_wiring_test.rs` + `[[test]] name = "integration_read_server_generation_wiring"`; spawns the real `CARGO_BIN_EXE_engram daemon --workspace <W>` with `mode = "read_server"`.

SPLIT (attempt-4 P2-6): the unit has five touched functions (`run_read_server_startup`, `install_generation_gate`, `drive_generation_activation`, `set_read_server_gate`, `read_server_gate`) and complexity high, which exceeds the task-granularity bound (<5 functions) and requires de-risking. It is decomposed into three sequential subtasks sharing this task's two files and harness: ST-a identity REPLACE + gate slot; ST-b install-before-ready + driver; ST-c transient retry + F54 determinism evidence. The task-level acceptance below is the gate for all three.

Test scenarios (3): (1) published fixture; (2) no root, empty root, corrupt, valid, transient; (3) managed mode and the non-git refusal.
