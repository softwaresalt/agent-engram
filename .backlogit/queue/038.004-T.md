Add async retry logic with exponential backoff around CozoDB write batches in
`index_workspace` so concurrent workspaces don't panic on SQLITE_BUSY during
write transactions.

Implement a new async retry wrapper using `tokio::time::sleep` (do NOT reuse
sync `run_script_retrying` from schema.rs). Follow same backoff parameters:
20 attempts, 25ms → 500ms exponential. Only retry on SQLITE_BUSY; propagate all
other errors. Retry at coarse per-file batch boundary, not per-individual-write.

## Acceptance Criteria

- Concurrent `index_workspace` operations succeed with retry instead of panicking
- `s_cs4` concurrent indexing test un-ignored and passes
- Retry attempts logged via `tracing::warn!` for observability
- No regressions in sequential indexing paths
