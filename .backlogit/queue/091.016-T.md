title: Avoid double read/parse in unsafe_module_prefixes canonical pre-pass
updated_at: 2026-07-16T09:00:36.1302726-07:00
---

Perf follow-up from 088-S (Copilot review PR #255). unsafe_module_prefixes() runs a global pre-pass that std::fs::read_to_string + parses every Rust file to collect non-default mod roots BEFORE per-file canonical resolution; the main index/sync loop then reads+parses each file again. This doubles I/O and parsing and performs blocking std::fs reads on the async index path. The pre-pass is architecturally required (unsafe prefixes must be known globally before any file's canonical resolution, because a top-level mod remap in one file affects path safety globally), so it cannot be folded into the incremental loop. Optimization: (1) switch the pre-pass reads to tokio::fs (non-blocking), and/or (2) cache the parsed (module, use_graph) contexts from the pre-pass and reuse them in the main loop to eliminate the second parse, trading bounded memory for CPU. Correctness-neutral: canonical edge output is byte-identical to the pre-cache baseline; purely performance. Delivered (Options 1+2): (1) the pre-pass reads via tokio::fs (non-blocking); (2) the parsed (module, use_graph) contexts are hash-checked and reused in the main pass to eliminate the second PARSE, with a recompute fallback on a hash mismatch. Acceptance: eliminate the duplicate canonical-context parse; no blocking fs reads on the async runtime; identical canonical edge output. Out of scope (deferred follow-up 091.021-T): the second file READ in the main/sync pass and the pre-existing pre-pass/main-pass TOCTOU on global unsafe-prefixes are both inherent to the two-phase pre-pass architecture; eliminating the read would require caching all source bytes (a single snapshot that would also close the TOCTOU) and is tracked as 091.021-T because it trades memory that scales with workspace size for I/O. Benchmark on a large workspace is deferred to 091.021-T.
