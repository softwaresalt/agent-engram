Eliminate the class of perceived-unreliability issues where users (and the developer) hit "engram won't load" or "engram is confused after /new" and have to manually clean up `.engram/run/` state. Issues are caused by stale runtime state, version drift between shim and daemon binaries, silent registry-source mismatches, workspace-hash drift across sessions, and lack of operator-visible health diagnostics.

Goal: make engram self-healing and self-diagnosing so the failure modes documented in this feature either cannot happen or surface a clear, actionable error before agents make tool calls.

<!-- BEGIN:AcceptanceCriteria -->
- Shim connecting to a stale daemon binary auto-respawns instead of hanging or returning opaque IPC errors. **(B1 / WS-1)**
- `engram doctor` returns a structured red/yellow/green report covering all eight failure modes above. **(B2 / WS-2)**
- Stale `engram.pid` for a dead process is detected and recovered automatically on next shim start. **(B1 / WS-3)**
- Registry referencing a missing required source surfaces a clear error with remediation hint, not silent skip. **(B2 / WS-4)**
- Two `set_workspace` calls with different canonical forms of the same path bind a single daemon. **(B1 / WS-5)**
- `set_workspace` returns within 500ms even on workspaces with thousands of changed files; scan completes in background. **(B2 / WS-6)**
- Integration tests cover all five regression scenarios listed in scope item 7 and run in CI. **(B1 delivers 3 of 5: version_mismatch, stale_pid_recovery, workspace_id_drift; B2 delivers remaining 2: registry_missing_source, multi_session_resume)**
- Telemetry counters increment correctly when injected failure modes are exercised. **(B2 / WS-8)**
<!-- END:AcceptanceCriteria -->

<!-- BEGIN:Motivation -->
Operator (developer) repeatedly hits engram load failures across sessions; root causes traced to stale daemon binary vs current shim, stale PID/lock from crashed shims, registry referencing renamed paths (`.backlog` -> `.backlogit`), workspace-hash drift across `/new` sessions spawning duplicate daemons, and offline-change detection looking like hangs. End users will perceive this as unreliability and abandon the tool.
<!-- END:Motivation -->

<!-- BEGIN:OutOfScope -->
- Multi-tenant single-daemon-many-workspaces redesign (current per-workspace daemon model is kept).
- Network/remote daemon transport (stdio/IPC only).
- Migration of historical `.engram/db/` state.
<!-- END:OutOfScope -->

<!-- BEGIN:Scope -->
Eight workstreams, each scoped to roughly one task or small task tree:

1. **Version handshake + auto-respawn** — embed protocol/build version in shim and daemon; mismatch triggers controlled respawn.
2. **`engram doctor` CLI + structured `health` field on `get_daemon_status`** — operator-visible diagnostics covering binary version, daemon liveness, pipe reachability, PID consistency, registry validity, workspace-id integrity.
3. **Self-healing PID/lock files** — PID liveness check, lock files with PID+start-time, atomic rename, pipe reachability probe.
4. **Strict registry validation** — every source path must exist or be `optional: true`; surface known-renamed-path migrations (e.g. `.backlog` -> `.backlogit`) with `engram doctor --fix` remediation.
5. **`.workspace-id` persistent identity** — eliminate duplicate-daemon spawns from cwd/symlink/canonical-path drift; reject ambiguous binds with a clear error.
6. **Background offline-change scan** — `set_workspace` returns immediately with `pending_scan: true`; progress visible via `get_workspace_status`.
7. **Integration test suite** — `stale_pid_recovery_test.rs`, `version_mismatch_test.rs`, `workspace_id_drift_test.rs`, `registry_missing_source_test.rs`, `multi_session_resume_test.rs`.
8. **Failure-mode telemetry** — counters for stale-PID-recovered, version-mismatch-respawn, registry-validation-failures, duplicate-daemon-detected; surfaced via `get_daemon_metrics`.
<!-- END:Scope -->

Recommended order (each item is roughly one harness feature):
