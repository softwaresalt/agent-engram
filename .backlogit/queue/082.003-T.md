PROVENANCE STORAGE — DB LAYER ONLY (re-split per Copilot #240 finding 1: the previous 082.003-T also required the CodeEdge model field + dehydration.rs + proptest_models.rs struct-literal changes, which pushed it to >=4 source files. The model/serialization half is now the separate task 082.011-T; this task is schema + DB read/write only).

Files (<=3: 2 src + 1 test): src/db/cozo_backend/schema.rs (extend `calls_edge` with a `resolution` attribute + forward migration), src/db/cozo_queries.rs (persist `resolution="direct"` in create_calls_edge :1206-1214 at the raw cozo-row level; add `count_calls_edges_by_resolution` + an enumerate-`calls_resolved_singleton` read query that returns RAW (from, to, resolution) rows/counts — NOT hydrated `CodeEdge` structs, so this task does NOT need the model field and can land before 082.011-T). Test: tests/integration/calls_edge_resolution_storage_test.rs.

Contract: today calls_edge stores only `(from, to) => created_at` (schema.rs:319; cozo_queries.rs:1206-1214 `:put calls_edge { from, to => created_at }`). Add a `resolution: String` attribute with a forward migration that DEFAULTS pre-existing rows to the exact string `direct`. create_calls_edge persists `resolution="direct"` for direct in-file edges; the post-pass (082.008-T) later writes the EXACT canonical value `calls_resolved_singleton` (never a shortened `resolved_singleton`) — the single source-of-truth string consumed by 082.004-T target-correctness checks and 082.010-T retraction. The read surface (`count_calls_edges_by_resolution` + enumerate) works on raw rows so 082.004-T can list/validate tagged edges without depending on the CodeEdge model field.

Width: schema (DB provenance storage). Scenarios (4): migration adds `resolution` and defaults existing rows to `direct`; a direct in-file edge persists `resolution="direct"`; count_calls_edges_by_resolution returns correct per-provenance counts; the enumerate query lists `calls_resolved_singleton` rows by provenance.

Depends on 082.002-T. Model/serialization propagation (`CodeEdge.resolution`) is the separate task 082.011-T, which depends on this one.
