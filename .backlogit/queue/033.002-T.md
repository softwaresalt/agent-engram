title: Parse multi-schema table references (schema.table syntax)
updated_at: 2026-04-28T17:41:43-07:00
---

Extend the SQL parser to handle schema-qualified table references such as `FROM public.users` or `INSERT INTO dbo.orders`. Currently only the first `identifier` child of `object_reference` is extracted; additional identifiers (the table name in dotted syntax) are lost.

Implementation (from plan Unit 3):
- `src/services/parsing/sql.rs`:
  - `extract_from_references`: Collect ALL `identifier` children from `object_reference` and join with `.` instead of breaking after the first.
  - `extract_insert_references`: Same change.
  - `extract_sql_name`: Same change for symmetry (affects CREATE TABLE/VIEW/FUNCTION qualified names). Per plan review P2-1, this extends scope beyond FROM/INSERT — accepted for consistency.

Discovery step: Add a debug test for `SELECT * FROM public.users` first to confirm tree-sitter-sequel 0.3 node structure for dotted identifiers (follows compound learning pattern).

Tests in `tests/unit/parsing_test.rs`:
1. `test_sql_schema_qualified_from` — `FROM public.users` → target `public.users`
2. `test_sql_schema_qualified_insert` — `INSERT INTO dbo.orders` → target `dbo.orders`
3. `test_sql_mixed_references` — both simple and qualified in one statement
4. `test_sql_schema_qualified_create` — `CREATE TABLE public.users` → class name `public.users`
Execution posture: Test-first (debug test → failing tests → implement).
