## Queue Sync Requests During Active Indexing

## Problem

When an agent session starts, the typical flow is:
1. `set_workspace` → triggers `background_db_hydration` (auto-indexing)
2. Agent immediately calls `sync_workspace` to ensure freshness
3. Gets `IndexInProgress` error → must poll/retry manually

With the 044.002-T fix, `sync_workspace` returns fast with `IndexInProgress` instead of timing out after 30s. But the caller still has no way to say "run sync after indexing finishes" — they must implement their own retry loop.

## Fix

Add a **queued-sync** mechanism:

1. Add a `pending_sync: AtomicBool` (or similar flag) to `AppState` (`src/server/state.rs`)
2. In `sync_workspace` (`src/tools/write.rs`), when `is_indexing()` is true:
   - Set `pending_sync = true`
   - Return `{"status": "queued", "message": "Sync queued — will run after indexing completes"}`
   - This is NOT an error — it's a successful acceptance of the request
3. In `background_db_hydration` (`src/tools/lifecycle.rs`), after `finish_indexing()`:
   - Check `pending_sync`
   - If true: spawn a `sync_workspace` task (coalesced — only one sync regardless of how many were queued)
   - Clear the flag after spawning

This gives callers a fire-and-forget sync that automatically executes at the right time.

## Acceptance Criteria

- `sync_workspace` during indexing returns `{"status": "queued"}` (not an error)
- Queued sync executes automatically after `finish_indexing()`
- Multiple queued requests coalesce into a single sync run
- Contract test: call sync during indexing → get queued response → after indexing completes, verify sync ran
- Integration test: spawn daemon, bind workspace, immediately call sync → get queued → wait for ready → verify graph is current
- `cargo test` passes
- `cargo clippy -- -D warnings -D clippy::pedantic` clean

## Scope

- `src/server/state.rs` — add `pending_sync` flag to `AppState`
- `src/tools/write.rs` — modify `sync_workspace` to queue instead of error
- `src/tools/lifecycle.rs` — drain pending sync after `finish_indexing()` in `background_db_hydration`
- `tests/contract/` — contract test for queued sync response
- `tests/integration/` — integration test for end-to-end queued sync

## Dependencies

Depends on 044.002-T (the `is_indexing()` guard must exist first so this task can replace the error path with the queued path)
