### T1b — Re-scope the skill's invariants and safety text for the new mode

The skill currently declares "**Report-and-halt only.** This skill NEVER
modifies the shipment manifest, queue files, or archive contents" (~line 56) and
"Report-and-halt is the only mutation path" (~line 118). `safe-close` is
mutating, so these invariants must be re-scoped **per mode** rather than
silently contradicted. The frontmatter `description`, "When to Use", Behavioral
Constraints and Quality Criteria are additionally framed around
`backlogit_ship_shipment` — the operation P-015 forbids by default.

Must also carry P-015's **full four-part Violation Action**: `git restore` /
`git revert`, re-verify the protected set, halt with the token **and** a P-005
broadcast naming the cascaded IDs, and "do NOT commit a corrupt backlog and do
NOT auto-prune the manifest."

- Skill domain: skill authoring (docs)
- Size: S | Complexity: high
- Depends on: T1a
- Acceptance criteria:
  - `pre` / `post` are documented read-only; `safe-close` is documented mutating.
    No unqualified "NEVER modifies" claim remains.
  - The P-015 **baseline integrity gate runs unconditionally**, and the protected
    set is verified after **every** archived manifest item **and again after the
    shipment-record archival** (closing the vacuity gap: manifest items are
    commonly pre-archived, so the item loop may execute zero iterations).
  - The `pre-archived` exemption applies to **manifest items only**; the protected
    set has **no** such exemption. Reviewer diffs this against P-015 for equivalence.
  - All four Violation Action elements are present.
  - `Select-String 'backlogit_ship_shipment'` returns only occurrences carrying
    the P-015 prohibition caveat or the fully-covered-root exception.
