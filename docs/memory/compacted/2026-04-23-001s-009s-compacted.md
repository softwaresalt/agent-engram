## Consolidated outcome

The 2026-04-23 ship work closed two related delivery threads. `001-S` landed an atomic policy TOCTOU fix by introducing `DispatchSnapshot` and `snapshot_dispatch_context()` so `src/server/state.rs` and `src/tools/mod.rs` could read workspace state under one simultaneous lock window. That change also added denied-policy usage telemetry, hardened the contract test harness, and resolved review feedback about read-guard ordering plus backlog ID collisions. The work was held at the merge gate pending human approval even after CI and review were green.

`009-S` completed the B2 daemon-reliability shipment for feature `029-F` across 19 backlog items. The shipped set covered daemon health diagnostics, strict registry validation, background scan generation/cancellation, reliability counters, socket permission hardening, and test coverage across contract, integration, and unit tiers. Key implementation decisions were to reset `hydration_ready` on every `set_workspace` call, treat unknown health as degraded (`Yellow`) instead of healthy, and verify Unix socket directory permissions by mode rather than UID so the code stayed within the workspace safety and `unsafe` constraints. One prior attempt to infer health and validity through narrower checks was rejected because it could mask stale-state or silent-failure cases.

Post-merge closure for `009-S` archived the shipment and backlog artifacts, updated `docs/ARCHITECTURE.md`, and graduated several compound learnings about daemon keying, directory mode behavior, and SurrealKV WAL recovery. The merge SHA recorded for the shipped closure was `0d831cad050c57ff538867a8025f46834ac1018f`. The closure also preserved follow-ups rather than burying them: the scan-generation race, pre-check for `.engram/`, and registry counter exposure remain explicit next-step items.

## Lessons retained

- Simultaneous read guards are required to close the TOCTOU window.
- Global metrics/tests need a field-specific discriminator to avoid cross-test interference.
- Health and readiness should fail closed when state is ambiguous.
- Archive/queue ID space must be checked together before creating new backlog items.
