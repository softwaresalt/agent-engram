* **`DOCTOR_SMOKE` descriptor classification (finding 9, stash `F95653D1`)**:
  Copilot flagged `DOCTOR_SMOKE` as declared `Read`/`read_server_available:
  true` while its implementation calls `Control`-classified operations.
  Investigated and confirmed this is the explicit plan-mandated acceptance
  criteria (not an oversight), already pinned by
  `doctor_smoke_is_a_read_server_readiness_workflow`. The real gap (F20's
  future mode-gated dispatch wiring) is out of `134-S`'s manifest scope
  (F19/`142.005-T` is descriptor-schema only) — deferred, not fixed.
* **`_shutdown` availability flip-then-revert (findings 10–12)**: initially
  flipped to `read_server_available: false` to match plan intent, then
  reverted to `true` after Copilot correctly showed `admit()` doesn't
  consult `AppState` and `process_request` executes `_shutdown`
  unconditionally regardless of mode — the flip would have made the
  registry actively misleading vs. runtime reality. Doc comments now name
  the gap explicitly, pointing to stash `1918AFD2` (F20 scope).
* **Release-build regression discovered post-merge (stash `6C9AA7D3`,
  this session)**: `cargo build --release` fails
  (`-D unused-imports`, `Duration` in `src/daemon/startup_activation.rs`,
  used only inside a `#[cfg(debug_assertions)]` test-only startup-delay
  hook). Confirmed genuine regression (file is new to `134-S`), not
  pre-existing; `cargo check`/`cargo build` (dev) and the full targeted
  test suite (39/39) are unaffected. `release.yml`'s actual release build
  step would fail identically — this currently blocks cutting a real
  release from `main`. Not fixed this session (out of scope for a
  non-destructive, evidence-only closure branch); flagged high priority
  for prompt Stage-planned remediation.
