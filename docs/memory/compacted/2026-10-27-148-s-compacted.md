## Outcome

Shipment 148-S delivered `142.077-T` (PRE-3b): `AppState` gained the `pub` `set_read_server_gate` /
`read_server_gate` slot, `run_read_server_startup` calls `install_generation_gate` after workspace
publication and before `set_hydration_ready_for_generation` when `generations_root` is a directory at
startup, and a spawned `drive_generation_activation` activates newly published revisions with a
100 ms to 2 s backoff. Feature PR #427 merged with merge commit
`952f76d1bf7596e4146ed7fa44ff55cdbf764db9`.

## Decisions

* A startup install failure with the root present is final: no driver is spawned (logged once at `warn`).
* A failed late install (root absent at startup) retries with log-once per error variant.
* The driver's manifest probe is probe-local: 1 MiB cap, regular files only, Unix `O_NONBLOCK` open,
  `spawn_blocking` under the activation deadline with one retained in-flight probe. The publisher's
  read path was deliberately left unchanged after a first attempt shared the capped reader.
* After a failed activation the driver re-probes and does not record a failure against a stale revision.

## Learnings

* Copilot re-reviewed after each push (three cycles): a blocking `spawn_blocking` probe needs a single
  retained handle and a non-blocking open, and a shared reader must not change publisher behavior.
* The `backlog_index_100_items_under_5_seconds` test sits near its threshold under load.
* The engram daemon (PID 2304) was no longer running at closure and the pipe was absent, so runtime
  probes were blocked again (stash `6B3DD712`). Advisory hardening follow-ups are stash `C8AEEFFA`.
