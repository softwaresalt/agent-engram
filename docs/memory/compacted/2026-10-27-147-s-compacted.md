## Outcome

Shipment 147-S delivered `142.076-T` (PRE-3a): `run_read_server_startup` in
`src/daemon/lifecycle_policy.rs` now takes workspace path, branch and `workspace_id`
from one `read_server_layout` call. `validate_workspace_path` and the inline
`canonicalize_workspace`, `resolve_git_branch` and `workspace_hash` calls are gone.
Feature PR #425 merged with a merge commit `a00a71bed94629eef44f478434083b77075b3070`.

## Decisions

* The non-Git refusal is raised in daemon endpoint derivation, before
  `run_read_server_startup`, so the scenario 3 non-Git case is a characterization guard
  that passes at HEAD; only the scenario 1 identity case went RED against the placeholder.
* The daemon creates an empty `.engram/run` directory before refusing; the guard asserts
  exactly that.
* The adversarial P2 (a missing path would map to `NotFound`, not `NotGitRoot`) is
  unreachable through the daemon, since endpoint derivation rejects a missing path first.

## Learnings

* The RED baseline for the whole PRE-3 family lives in the `142.076-T` task comments;
  `142.077-T` and `142.064-T` compare against it.
* The daemon stayed `starting` after a branch switch even with a 180 s plus 180 s
  `set_workspace` re-latch, so runtime probes were blocked again (stash `6B3DD712`).
