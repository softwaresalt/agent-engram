## 028-S — CLI Hardening and Startup Validation (043-F)

**Merge**: PR #90 + review fixes PR | **Branch**: `feat/cli-hardening-startup-validation`

**Root causes discovered** (in order):
1. SurrealQL in help text (schema drift) → fixed in `engram.rs`, `gate.rs`, `tools_catalog.rs`
2. Null IPC request IDs → `runner.rs` auto-generates `"1"` when `--id` not supplied
3. `--depth` help said "default 2" but handler used 1
4. Daemon never reached Ready — `set_hydration_ready()` called AFTER `sync_code_graph`
5. `.copilot/logs/` 1 GB+ files hashed on every scan → MAX_HASH_FILE_BYTES = 10 MiB guard
6. SQLITE_BUSY — auto-sync raced with `background_db_hydration`; lock guarded with `acquired_lock`
7. Watcher init blocked `set_workspace` spawn → ordering fixed in `ipc_server.rs`
8. `db_path` in `get_workspace_status` used old SurrealDB path
9. `code_graph` stats queried unconditionally → gated on git-graph feature
10. `ENGRAM_DATA_DIR` inherited by test subprocesses → `.env_remove` added to all 3 harness spawns + `spawn_daemon`
11. Test harness deadline off — MAX_ATTEMPTS polling fixed
12. `let _ = try_start_indexing()` discarded return → `acquired_lock` guard added

**Key decisions**:
- `set_hydration_ready()` is called BEFORE `sync_code_graph` (clients get "ready" promptly; tool handlers guard via `is_indexing()`)
- `.env_remove("ENGRAM_DATA_DIR")` in both DaemonHarness and `spawn_daemon` — isolates ALL daemon spawns
- MAX_HASH_FILE_BYTES = 10 MiB: files >10 MiB not hashed for change detection (acceptable trade-off)

**Bugs deferred**: BUG-B (`B6F12A12`) SQLITE_BUSY during indexing; BUG-C (`D3C7173A`) 30s IPC timeout during indexing

**Files**: `src/bin/engram.rs`, `src/services/gate.rs`, `src/shim/tools_catalog.rs`, `src/cli/runner.rs`, `src/tools/lifecycle.rs`, `src/daemon/ipc_server.rs`, `src/daemon/watcher.rs`, `src/services/file_tracker.rs`, `src/models/config.rs`, `src/shim/lifecycle.rs`, `tests/helpers/mod.rs`

## 030-S — CLI-Direct Daemonless Mode (045-F)

**Merge**: PR #96 (+ #94 staging, #95 review fixes) → `d09bba0` at 2026-05-08T22:50:19Z

**What shipped**: `engram sync --direct` / `engram index --direct` bypass the daemon entirely. `DaemonLock` prevents concurrent operation. `ENGRAM_DIRECT=1` env var supported via `BoolishValueParser`. Freshness detection: `sync_workspace` records per-file hashes so daemon's `detect_offline_changes` returns 0 after a `--direct` run.

**Key decisions**:
- `DaemonLock` acquired in `run_direct_sync` — exit 2 if already held (daemon running)
- `Box::leak` for lock guard — intentional: one lock per process lifetime, OS reclaims on exit
- `BoolishValueParser` required for `ENGRAM_DIRECT=1` (clap 4 default bool parser only accepts "true"/"false")
- `record_file_hash_precomputed` added to avoid double disk I/O in sync loop
- `count_code_files` fast-path in `hydrate_code_graph` — skips JSONL reload when DB already populated
- Tautological unit tests removed from `indexing.rs`; integration tests provide real coverage
- Test cases 3 (daemon mutex) and 5 (no orphaned processes) deferred — require `DaemonHarness` subprocess infrastructure

**Staging (PR #94, #95)**: 5 Copilot review comments on plan/staging docs addressed; all review threads resolved via GraphQL

**Review rounds on PR #96**: 13 Copilot review threads (2 rounds), all fixed and resolved via GraphQL

**Failed approach**: Initial `BoolishValueParser` was wrong type — replaced with `value_parser!(bool)` / `BoolishValueParser::new()`
