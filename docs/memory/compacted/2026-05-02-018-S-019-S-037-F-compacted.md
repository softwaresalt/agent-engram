### U015-FLK1 Three-Layer Fix

1. **Layer 2 — fd-lock scope**: `run_schema_bootstrap` moved inside `spawn_blocking` closure in `connect_db`
   (`src/db/cozo_backend/mod.rs`). fd-lock held through both `DbInstance::new` AND schema bootstrap.
   Commit: `e85ee80`.
2. **Layer 3a — schema retry**: `run_script_retrying` added to `schema.rs` — 20-attempt exponential
   back-off (25 ms → 500 ms, ≈7.8 s worst case). Commit: `6f64eb7`.
3. **Layer 3b — startup auto-sync retry**: `ipc_server.rs` startup auto-sync wraps `sync_workspace`
   in 10-attempt retry (50 ms → 500 ms) on SQLITE_BUSY. Commit: `6f64eb7`.

### Windows fd-lock Intra-Process Note

`LockFileEx` advisory locks on Windows allow the same process to re-acquire the same byte range
via different file handles. Retry back-off is required as the second safety net for intra-process races.
