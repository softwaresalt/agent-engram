## Problem

Existing MCP catalog coverage derives its expectations from the production
catalog it is meant to validate, so it cannot detect drift in the dimensions
agents actually consume.

## Evidence

### E1 — The current test reads from production

`tests/contract/tools_catalog_test.rs` opens with
`use engram::shim::tools_catalog;` and every assertion calls
`tools_catalog::all_tools()`:

* `task_management_tools_absent_from_catalog` — builds a `HashSet` of
  `all_tools()` names and asserts 29 removed names are absent.
* `retained_tools_present_in_catalog` — asserts 14 retained names are present.
* `tool_count_constant_matches_catalog` — asserts `TOOL_COUNT` equals
  `all_tools().len()`, comparing production against production.

### E2 — Only names are independently declared

`REMOVED_TOOLS` and `RETAINED_TOOLS` are hardcoded name lists, so **names** have
a partial independent oracle. **Descriptions and input object schemas have none.**
Nothing constrains what a tool's description says or what its JSON Schema
declares.

### E3 — Name coverage is presence/absence, not exactness

The assertions check that 14 names are present and 29 are absent. A tool added
under a new name, or a retained tool silently renamed alongside its list entry,
passes. There is no exact set equality against a declared expectation.

### E4 — The agent-visible surface is never observed

Agents consume the serialized `tools/list` result over the MCP stdio transport —
`ListToolsResult` produced by `ShimHandler::list_tools`
(`src/shim/transport.rs`), which itself calls
`crate::shim::tools_catalog::all_tools()`. Existing tests inspect in-process Rust
structures. Any drift introduced during serialization — a schema field that
does not survive to JSON, a description dropped, a property renamed — is
invisible to the current tests.

### E5 — The derivation path is shared

Because both the production catalog and its test read `all_tools()`, a defect in
`all_tools()` is reflected identically on both sides of every comparison. The
oracle and the subject share a derivation path, which is precisely the property
the stash entry says must not exist.

## Root Cause

The catalog has a *self-referential* oracle. Test expectations are computed from
the artifact under test for every dimension except a partial name list, and the
observation point is the in-process struct rather than the agent-visible
serialized response.

## Chosen Direction

**A declarative, human-maintained fixture validated against the serialized
agent-visible response.**

1. **Independent expectation source.** A checked-in fixture (JSON) declares, for
   every tool, the exact name, the description, and the full input object schema.
   The fixture is authored and reviewed by humans and is never generated from
   `all_tools()` at build or test time.
2. **Agent-visible observation point.** The oracle validates the serialized
   `tools/list` JSON as an MCP client receives it, not the Rust structs. This
   catches serialization drift (E4).
3. **Exact set equality.** Name sets must match exactly — no extras, no missing —
   replacing presence/absence checks (E3).
4. **Schema-shape assertions.** For each tool: `type` is `object`, the property
   name set matches exactly, each property's declared type matches, the required
   list matches, and `additionalProperties` handling matches.
5. **Description assertions.** Description present, non-empty, and equal to the
   declared expectation, since the description is the primary signal an agent
   uses to select a tool.
6. **Drift reporting.** On mismatch, emit a precise per-tool diff (added,
   removed, changed name / description / schema) plus a documented fixture-update
   procedure so an intentional catalog change is a reviewed fixture edit.

## Independence Guarantee

The oracle must satisfy a mechanical independence property, not just an
intention:

* The oracle test must not import `engram::shim::tools_catalog`, and must not
  reach `all_tools()` through any helper.
* The fixture must not be regenerated by any build script, test, or CI step.
* Updating the fixture must be a deliberate, reviewable source edit.

This guarantee is itself asserted, so a future refactor cannot quietly reconnect
the oracle to the production derivation path.

## Rejected Alternatives

| Alternative | Why rejected |
|---|---|
| Snapshot test generated from `all_tools()` | Shares the derivation path (E5); a wrong catalog produces a matching wrong snapshot. |
| Extend the existing test with more name entries | Leaves descriptions, schemas, and the serialized surface uncovered (E2, E4). |
| Validate against the MCP specification only | Confirms well-formedness, not that engram exposes the intended tools with the intended contracts. |
| Auto-generate the fixture on first run, then freeze | The first run bakes in whatever the catalog currently says, including any existing defect. |

## Relationship to Existing Coverage

`tests/contract/tools_catalog_test.rs` is retained. It answers a different
question — that a specific historical removal stayed removed. The new oracle is
additive and independent; neither may import the other's expectations.
