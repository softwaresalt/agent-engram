## Verification boundary

This record separates evidence available before a tag exists from checks that
can only run against hosted release assets. G1 does not create a local or
remote tag, upload an asset, or publish or edit a GitHub Release.

| Evidence class | Meaning |
|---|---|
| Pre-tag static evidence | Source, workflow, and local package checks that can be completed at G1 |
| Post-publish required | Proof that must come from the exact hosted archives after separate G2 and G3 approvals |

### Tier 2 - packaged archive checks

The version assertion is always executed from a binary unpacked from an
archive. A local `cargo run`, a binary in `target/`, or Cargo metadata is not
acceptable version evidence.

| Archive | G1 status | G3 requirement |
|---|---|---|
| `engram-v0.3.0-rc.1-x86_64-unknown-linux-gnu.tar.gz` | Post-publish required | Unpack on Linux; verify `engram`, `README.md`, `LICENSE`, `--version`, and `--help` |
| `engram-v0.3.0-rc.1-x86_64-pc-windows-msvc.zip` | Local same-layout package smoke to be recorded before G1 closes | Repeat against the hosted Windows archive |
| `engram-v0.3.0-rc.1-aarch64-apple-darwin.tar.gz` | Post-publish required | Unpack on Apple ARM; verify `engram`, `README.md`, `LICENSE`, `--version`, and `--help` |

The local Windows package used the Release workflow's archive layout and passed
on 2026-08-29:

```text
ARCHIVE_TARGET=x86_64-pc-windows-msvc
ARCHIVE_VERSION_OUTPUT=engram 0.3.0-rc.1+g3a5ca3b5-dirty
MCP_PROTOCOL_VERSION=2025-11-25
MCP_TOOL_COUNT=21
MCP_STDIN_CLOSE_EXIT=10
ARCHIVE_SMOKE=PASS
```

The `-dirty` build suffix identifies this as pre-commit G1 evidence, not a
hosted release asset. The version value came from the unpacked archive binary.
Only the G3 rerun against the clean, tagged, hosted archive can prove the final
asset.

The version-generic verifier is:

```text
python scripts/verify-release-archive.py \
  --archive <archive> \
  --tag <vMAJOR.MINOR.PATCH[-PRERELEASE]> \
  --target <target-triple> \
  --work-dir <new-empty-directory> \
  [--mcp]
```

### Tier 3 - MCP stdio checks

On Linux and Windows, add `--mcp`. The verifier sends `initialize` and
`tools/list` to the unpacked archive binary. It requires:

* an `initialize` result with `serverInfo` and `protocolVersion`
* a non-empty `tools` array
* JSON-only stdout
* bounded exit after stdin closes, with no panic

The check deliberately passes a nonexistent workspace. The serve-first shim
must still answer `initialize` and `tools/list`, then exit with the documented
`admission_failure` code `10`. This isolates MCP stdio behavior from the known
daemon-readiness defect and does not turn a readiness timeout into an RC gate.
The verifier prints `MCP_PROTOCOL_VERSION`, `MCP_TOOL_COUNT`, and
`MCP_STDIN_CLOSE_EXIT` for the evidence record.

## G3 post-publish verification

These checks remain blocked until the operator separately approves merge and
then tag/publication:

1. Record the completed `Release` workflow URL and exact tagged commit.
2. Confirm `validate-tag`, quality gates, changelog, all three build matrix
   legs, and publication succeeded.
3. Download each hosted archive to its matching native platform.
4. Run the Tier 2 verifier on all three hosted archives.
5. Run the Tier 3 verifier with `--mcp` on the hosted Linux and Windows
   archives.
6. Record each unpacked archive's exact `ARCHIVE_VERSION_OUTPUT`. All must
   contain `0.3.0-rc.1`.
7. Record the Linux and Windows `MCP_PROTOCOL_VERSION`, tool count, and
   stdin-close exit.
8. Confirm the release body is non-empty and begins with the curated RC
   disclaimer.
9. Confirm GitHub marks `v0.3.0-rc.1` as **Pre-release** and still marks
   `v0.2.0` as **Latest**.

Failure of any hosted archive is a full-stop publication defect because the
build matrix uses `fail-fast: true` and publication uses
`fail_on_unmatched_files: true`. Do not represent partial asset success as a
valid RC.
